## 一、现状实现（`public/assets/toast.js`，已达标的部分）

```js
toast(msg, kind)
  kind: true | 'bad' | 'err' | 'error'  → 失败
        'good' | 'ok'                  → 成功
        其它/省略                       → 中性

失败（err）：常驻，不排定时器；点击关闭；同时 console.error 留痕
成功：2400ms 自动消失
```

**已经做对的三件事**（不要回退）：
1. **失败常驻** —— 满足「不能 2 秒消失」。
2. **样式由 toast.js 自己注入**（`ww-toast-style`），不依赖各页 CSS —— 这条很关键，书房不引 `room.css`，若交给页面 CSS 必然出现「某页失败不变色」。
3. **无 `#toast` 元素时不静默** —— 失败走 `console.error`，成功走 `console.log`。

## 二、契约：三条要求逐条落地

### A.1 签名统一为 `notify(msg, { tone })`，`tone` 必填无默认

**现状差距**：`toast(msg, kind)` 的 `kind` 可省略（省略=中性），这就是「错误被当成功」的入口——漏传一个参数，失败提示就变成 2.4 秒消失的中性提示。

**契约**：

```js
// 唯一签名。tone 必填，缺失即抛错（开发期暴露，不静默降级）
Notify.show(message, { tone, key?, sticky? })
//   tone: 'error' | 'success' | 'info'   ← 必填，无默认值
//   key:  相同 key 不堆叠，只更新计数（防连点 3 次出现 3 条一样的话）
//   sticky: 仅 'error' 可显式传 false（用于已知可恢复的轻错误）

Notify.close()            // 主动收起当前条
Notify.history()          // 返回最近 20 条（内存，刷新即清）
```

**迁移映射（保持向后兼容，避免一次性改 78 处调用点）**：

| 旧写法 | 新写法 |
| --- | --- |
| `toast(msg)` | `Notify.show(msg, { tone: 'info' })` ← **必须人工判断是 info 还是 error**，不能机械映射 |
| `toast(msg, true)` / `'bad'` / `'err'` | `Notify.show(msg, { tone: 'error' })` |
| `toast(msg, 'good')` / `'ok'` | `Notify.show(msg, { tone: 'success' })` |

**当前调用点统计（改动面）**：

| 页面 | 单参（需人工判定 tone） | 双参（可机械映射） |
| --- | --- | --- |
| 下载中心 | 4 | 6 |
| 书房 | 4 | 13 |
| 五五客厅 | 5 | 3 |
| 媒体库 | 4 | 7 |
| 投屏 | 1 | 15 |
| 相册 | 4 | 5 |
| 笔记库 | 3 | 7 |
| 追更日历 | 8 | 16 |
| **合计** | **33** | **72** |

**33 处单参必须逐个判断语义**——这是本契约唯一的真实工作量，也是不能自动化的一步。

**过渡策略**：保留 `window.toast` 作为兼容别名（内部转调 `Notify.show`，单参默认 `tone:'info'`），
但**加一条开发期告警**：`if (!kind) console.warn('[toast] 未传 tone，按 info 处理：' + msg)`。
跑一周收集实际漏传清单，再逐个修正为 `error`，最后删别名。

### A.2 `tone:'error'` 时长 —— 实测数据与总管给的数字不符

总管说「取投屏的 4200ms」。**实测当前全站已统一为「失败常驻、不设时长」**，比 4200ms 更强：

```
投屏旧实现  toast(msg, kind) → bad: 4200ms
投屏当前    已委托 toast.js  → 失败常驻（无定时器）
```

**契约取「常驻」，不取 4200ms。** 理由：
- 4200ms 仍然是「会消失」——用户去倒杯水回来就没了，问题只被推迟 1.8 秒。
- 常驻 + 点击关闭已在 8 页落地并验证（S5 ✅）。
- 总管的第 ③ 条自己说了「延长到 4200ms 只是把坑挖浅一点」，我按第 ③ 条执行。

**成功/中性保留 2400ms**（`SUCCESS_MS`），不再按页面分档。

### A.3 回看入口 —— **这是当前唯一真正的缺口**

**实测证据（`toast.js:61-66`）**：

```js
if (k === 'err') {
  t.title = '点击关闭';
  t.onclick = function () { t.className = 'toast'; t.onclick = null; };
  try { console.error('[toast] ' + text); } catch (_) {}
  return;                       // 常驻
}
```

**失败会常驻，但用户一点关闭，这句话就永久消失**：
- 没有内存队列（`grep -cE 'localStorage|history|queue'` → **0**）
- 除了 `console.error`（普通用户不会开控制台）**没有任何回看通道**
- 8 个页面里 **0 个**有「消息 / 记录」入口

**所以总管那句「10 秒后还能不能读到」现在的答案是：读不到。** 常驻只是让窗口从 2.4 秒变成「直到用户点掉」，点掉即丢失。

**契约（缺一不合格）**：

```
Notify.history()  → 最近 20 条 [{ time, page, tone, message }]
入口位置          → 每间房页脚固定一个「消息」按钮
显示条件          → 仅当存在未读 error 时显示，带角标数字
点开              → 列表：时间 + tone + 完整文本 + 复制按钮
保留策略          → 仅内存，刷新即清；上限 20 条
空态              → 「还没有失败记录」
```

**判据（可测，缺一不合格）**：

```
1. 制造一次失败 → 「消息」按钮出现且角标=1
2. 等 10 秒（原 toast 早已消失）→ 点「消息」→ 能读到那条完整文本
3. 点 toast 上的关闭 → 那条记录仍在 history 里（关掉的是浮层，不是记录）
4. 成功操作 → 不产生 error 记录、角标不增加
5. 同 key 连点失败 3 次 → history 只有 1 条，但带 ×3 计数
6. 复制按钮 → 剪贴板 = 原文
```

**第 3 条是本契约的核心**：区分「关闭浮层」与「删除记录」。现在两者是同一件事，这是缺陷根因。

## 三、失败长相（修复后仍可能出现的坏结果）

| 坏结果 | 为什么坏 | 判据 |
| --- | --- | --- |
| 「消息」按钮常在但列表永远空 | 用户以为有记录，点开什么都没有 | 无 error 时按钮不显示 |
| 关闭 toast 同时删掉记录 | 等于没做回看 | 判据 3 |
| 记录落 localStorage 越积越多 | 体积与隐私 | 刷新后清空，≤20 条 |
| 单参调用全被机械映射成 `info` | 33 处失败提示仍会 2.4 秒消失 | 开发期告警跑一周，漏传清单为 0 才删别名 |
| 样式交给各页 CSS | 书房不引 room.css → 失败不变色 | 样式必须由 toast.js 注入（现状已对，勿回退） |

## 四、退役路径

若「消息」按钮一时做不出来，**最小可交付**是：
`Notify.history()` 先在控制台暴露（`window.__wwHistory`），并给失败 toast 加一行「最近失败 N 条，控制台查看」。
这条**不算完成**（普通用户不开控制台），只作为过渡，要写进攻克表。
