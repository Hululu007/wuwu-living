## 零、一句话结论

**契约本身写得不错，缺的是「可执行」和「六态的后三态」。**

视觉契约有 token 表但没有间距/阴影/字号阶梯；交互契约在规范里只有 1 处提到「空态」，六态没有成文；命名契约完全不存在（`返回五五客厅` 与 `回客厅` 并存，靠人记）。

## 一、视觉契约现状

### 1.1 已有的（这部分是对的）

`public/assets/room.css` 定义 **25 个 token**，覆盖：底色/主文字/次级/辅助/两条分隔线/品牌色 + 十间房色 + 三个语义色 + 两个字体族。

```
--bg #0a0d0b   --ink #efe9dd   --muted #c0b7a9   --faint #9c9589
--line / --line2  --brass #c4a36e
--ok --warn --danger
--magnet --book --music --vod --download --library --notes --calendar --photos --cast
--serif --sans
```

### 1.2 缺的（阶梯层面）

| 项 | 现状 | 实测 |
| --- | --- | --- |
| 间距阶梯 | **无 token，无基准网格** | 24 档取值，**15 档脱离 4 倍数**（2/3/5/6/7/9/10/11/14/17/18/22/26/30/34） |
| 字号阶梯 | **无 token** | 13 档（10/10.5/11/11.5/12/12.5/13/13.5/14/19/26/30/33），**6 处 < 11px**，违反《前端设计规范.md》第 36 行「辅助文字不小于 11px」 |
| 阴影 | **无 token** | 仅 3 处 `box-shadow`，全部写死 |
| 圆角 | 无 token | 取值 1/2/3/**8**，8 超出「面板 2–3px」 |

### 1.3 裸色值（总管已认的三条之一）

| 位置 | 裸色值数 | 最重项 |
| --- | --- | --- |
| `room.css`（:root 外） | **47** | `rgba(255,255,255,.X)` 用了 **14 种不同透明度**（.022/.025/.03/.035/.04/.045/.055/.07/.075/.08/.09/.1/.12…） |
| 页面内联合计 | **343** | 书房 158 / 五五客厅 80 / 投屏 42 / 相册 … |

### 1.4 一条硬缺陷：语义色被房色占用

```
--warn  = --book   = #d6a05e
--danger = --music = #dd7768
```

**后果**：书房房色与「警告」同色；音乐房色与「危险/失败」同色。用户看到 `#dd7768` 时，无法判断这是「音乐房的信号」还是「操作失败了」。这正是「去色测试」要拦的东西——色盲用户直接失去这一层信息。

### 1.5 一条硬缺陷：近似色漂移

`#efe9df` 出现 **5 次**，而 `--ink` 是 `#efe9dd`——**只差最后一位**。这不是新颜色，是抄手抄歪。同类：`#15130f`/`#15110c`、`#0b0e0c`/`#0b0c0e`/`#0c100d`。

## 二、交互契约与六态矩阵（本轮重点）

### 2.1 六态定义（本项目版）

| 态 | 判定标准（可测） |
| --- | --- |
| 空 | 无数据时有说明 + 下一步动作，不是空白 |
| 正常 | 有数据 |
| 加载 | 有 spinner/skeleton/「读取中」占位，且**占位与最终内容同尺寸**（不跳版） |
| 出错 | 有错误文案，**且与「空」在视觉上可区分**（不同图标/色彩/边框） |
| 超量 | 列表被截断时告知「还有多少」，且**计数不得用截断后的长度** |
| 不可用 | 功能降级/无权限/离线时有明确说明 + 为什么 |

### 2.2 实测矩阵（✅ 有 / ⚠️ 有但不合格 / ❌ 无 / – 不适用）

| 房间 | 空 | 正常 | 加载 | 出错 | 超量 | 不可用 |
| --- | --- | --- | --- | --- | --- | --- |
| 五五客厅 | ✅ | ✅ | ✅ | ⚠️ 有文案无区分 | ❌ 待办静默截 5 条 | ❌ |
| 书房 | ✅ | ✅ | ✅ | ⚠️ 有文案无区分 | ⚠️ 书架截 20 本无提示 | ❌ |
| 媒体库 | ✅ | ✅ | ❌ | ⚠️ 有文案无区分 | ❌ **把 5 当总数上报** | ❌ |
| 相册 | ✅ | ✅ | ✅ | ⚠️ 有文案无区分 | ❌ | ❌ |
| 笔记库 | ✅ | ✅ | ❌ | ⚠️ 有文案无区分 | ❌ | ❌ |
| 下载中心 | ✅ | ✅ | ❌ | ⚠️ 有文案无区分 | ❌ | ❌ |
| 追更日历 | ✅（6 处空态文案，最全） | ✅ | ❌ | ⚠️ 有文案无区分 | ❌ | ❌ |
| 投屏 | ✅ | ✅ | ❌ | ❌ **唯一完全没有出错呈现** | – | ❌ |

**汇总：48 格中 ✅ 17 / ⚠️ 8 / ❌ 23。**

### 2.3 哪几态现在根本没实现（总管问的就是这个）

**第一档·全站 0 实现（8/8 间房都缺）**

1. **不可用**——`无权限 / 不可用 / 离线 / 未授权` 全站 **0 次**命中。所有失败都退化成 toast，没有「为什么不能用、能不能修」的说明。投屏的 USB 调试提示算唯一例外。
2. **超量**——没有任何一处告知「还有多少」。

**第二档·部分缺失（5/8 缺加载）**

3. **加载**——媒体库（10 个 fetch）/ 笔记库（6）/ 下载中心（1）/ 追更日历（3）/ 投屏（1），**五个房间零 loading 容器**。有 fetch 却没加载态 ⇒ 网络慢时用户看到的是空白页，会以为坏了。

**第三档·实现了但等于没实现（7/8）**

4. **出错**——7 间房都渲染了「媒体库没读出来」这类文案，**但全部复用 `.empty` 样式**（虚线框 + 居中 + 同一字体），与「暂无数据」长得一模一样。用户分不出「坏了」还是「空着」。投屏连文案都没有。

### 2.4 超量的两处真实证据（不是推测，是代码逻辑）

**证据 A / 媒体库：把截断后的数当总数上报**

`public/媒体库.html:248-251`
```js
watched = watched.slice(0, 5);              // 先截断
$('#continueCount').textContent = watched.length + ' 部在看';  // 再拿截断后的长度报数
```
⇒ 有 12 部在看时，界面显示「**5 部在看**」。这是**撒谎**，不是「少显示」，用户永远不知道另外 7 部存在。

**证据 B / 书房：书架超过 20 本就点不到**

`public/书房.html:920` `S.shelf.slice(0, 20)` —— 但 `:887` 的 `statShelf` 显示的是**真实总数**。有 25 本时，界面说「25 本」，只画 20 个，**后 5 本无法打开、无法移出**，也没有任何提示。

**证据 C / 五五客厅：待办静默截 5 条**

`:730` `todos.slice(0, 5)`，无「还有 N 条」。第 6 条待办彻底不可见。

### 2.5 点击深度

首页十间房 `data-id` 入口 **10/10 齐全**，房间 → 内容均 ≤ 2 层。**这条是合格的。**

## 三、命名契约现状

**规范里没有任何命名条款，这是三份契约里唯一完全缺失的一份。**

### 3.1 实测：返回入口的可见文字与无障碍文字不一致（7/8 间房）

| 房间 | 可见文字 | title / aria-label |
| --- | --- | --- |
| 下载中心 / 媒体库 / 笔记库 / 相册 / 追更日历 / 投屏 | `回客厅` | `返回五五客厅` |
| 书房 | `客厅` | `返回五五客厅` |
| 五五客厅 | `55`（brand） | `五五客厅首页`（**合理，不算缺陷**） |

**根因**：不是两个控件，是**同一个 `<a>` 的三处文字不一致**。视觉用户看到「回客厅」，屏幕阅读器念「返回五五客厅」，语音控制用户说「回客厅」点不动。这不是「命名风格不统一」，是**可访问性缺陷**。

（我一开始把五五客厅的 `55 / 五五客厅首页` 也报成不一致，那是误报——品牌 logo 不是返回入口，已从判据里排除。）

### 3.2 已确认不是缺陷的

- **每页只有一个可见「回客厅」入口** —— 8/8 合格。上次那个「两个返回客厅」确实修完了。

### 3.3 toast：8 份复制，3 种实现

```
下载中心 / 媒体库 / 相册 / 笔记库 / 追更日历  → 实现 A（md5 3c7aa1b7…，5 份完全相同）
五五客厅                                       → 实现 B
书房                                           → 实现 C（有 2 处 function toast）
投屏                                           → 实现 D
```
`assets/` 里没有共享定义。⇒ 改一次 toast 要改 8 个文件，必然漂移。

### 修掉的三处自身误报（先自报，别让总管抓）

1. **N3 误报** —— 按 `data-room` 统计只找到 3 个入口，判「首页缺 7 间房」。真因：十间房目录用的是 `data-id`（`data-room` 只有 3 个可点 cell 用）。修后 10/10 PASS。
2. **N1 误报** —— 把 `.brand` 品牌 logo（「55 / 五五客厅首页」）当返回入口报不一致。品牌名与无障碍标签本来就不该同词。已排除 `.brand`。
3. **token 解析假绿** —— 原按行匹配 `--x:` 定义，`bad` 夹具把 `:root` 写成单行时一个都抓不到 ⇒ V3/V4 空过显示 PASS。这比误报更危险。已改为全文正则 + 先剥定义再数裸色值。

**另有两处「空数据当通过」的假绿已修**：V5/V6/V7 在找不到任何取值时，原判 PASS，现判 **未取证**。
