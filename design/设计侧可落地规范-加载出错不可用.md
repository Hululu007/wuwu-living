## 一、加载态容器规范

### 1.1 唯一结构（三种变体，按场景选）

```html
<!-- A 列表/网格：骨架屏（推荐，不跳版） -->
<div class="loading" role="status" aria-live="polite">
  <span class="spinner" aria-hidden="true"></span>
  <span>正在读取任务…</span>
</div>

<!-- B 已知条数：骨架卡（媒体库/相册这类网格） -->
<div class="skeleton-grid">
  <div class="skeleton-card"></div> ×3~6
</div>

<!-- C 详情/单对象：文字 + 转圈即可 -->
<div class="loading" role="status" aria-live="polite">
  <span class="spinner" aria-hidden="true"></span>
  <span>正在加载…</span>
</div>
```

**硬要求（三条，缺一不合格）**：
1. **必须有 `role="status"` + `aria-live="polite"`** —— 否则屏幕阅读器不知道「正在加载」。
2. **`spinner` 必须 `aria-hidden="true"`** —— 装饰元素，别让读屏念出「旋转」。
3. **占位高度必须接近最终内容高度**（±30%）—— 否则加载完成时页面跳版，用户会以为点错了。

### 1.2 哪些位置必须有，哪些不要

| 位置 | 要不要 | 理由 |
| --- | --- | --- |
| 列表/网格首次加载 | **必须** | 空白最容易被读成「没有数据」 |
| 详情/弹层首次打开 | **必须** | 同上 |
| 轮询刷新（已有内容） | **不要** | 已有内容时再盖一层转圈会让用户以为内容没了；改用角落小字「刷新中…」 |
| 提交按钮点击后 | **不要** | 按钮自身改文案 + 禁用即可（`提交中…`），别盖全屏 |
| 耗时 < 300ms 的操作 | **不要** | 闪现的转圈比没有更烦 |

**判据**：
```
1. fetch 发出后、返回前，容器内有可见占位且 getBoundingClientRect().height > 0
2. 返回后占位消失，内容出现，页面 scrollY 变化 < 50px（不跳版）
3. 轮询刷新时不出现 .loading（只有首次出现）
```

### 1.3 现状要收敛的一处

现在有两种写法并存：
```html
<!-- 写法 A：5 处，JS 注入，带 aria -->
<div class="loading" role="status" aria-live="polite">' +

<!-- 写法 B：1 处，静态 HTML，用 hidden 控制 -->
<div class="loading" id="loading" hidden><span class="spinner"></span>正在…</div>
```
**统一到 A**。理由：`hidden` 写法在 JS 失败时会永久显示「正在…」（假加载），而 JS 注入的写法如果 JS 挂了就是空白——**空白比假加载诚实**。

## 二、出错态与空态的视觉区分

### 2.1 现状：已实现，做法是对的

`.empty.error` 已经落地，而且是**四维度同时区分**（不只靠颜色）：

| 维度 | 空态 `.empty` | 出错 `.empty.error` |
| --- | --- | --- |
| 边框形状 | **虚线** `dashed` | **实线** `solid` |
| 边框颜色 | 中性 `--line` | 危险色 `rgba(222,66,23,.45)` |
| 对齐 | 居中 `center` | **左对齐** `flex-start` |
| 左侧竖条 | 无 | **3px 粗竖条** |
| 按钮 | 无 | **有重试** |

**这满足「四者至少两个不同」的要求，而且灰度下仍可分**（虚线 vs 实线、居中 vs 左对齐、有无按钮，都是形状差异）。

### 2.2 文案规范（现在不统一，要收）

| 态 | 文案格式 | 例子 |
| --- | --- | --- |
| 空 | `<b>还没有 X</b><span>怎么才会有：…</span>` | `还没有下载任务` / `粘贴磁力或直链，回车开始` |
| 出错 | `<b>X 没读出来</b><span>原因</span><button>重试</button>` | `媒体库没读出来` / `连接超时` / `重试` |

**硬要求**：
- 空态**必须给「怎么才会有」**，不能只说「暂无数据」（用户不知道下一步）。
- 出错**必须给「重试」或「怎么办」**，不能只有一句报错。
- **禁止**：「加载失败」「出错了」「未知错误」这类无信息文案。

### 2.3 现状缺口

7 间房都有 `.empty.error`，但**文案格式不一致**。这条我没逐条核，属可改进项，不是当前阻塞。

**当前 6/8 覆盖，仍缺 2 间**：`媒体库` / `笔记库`。（书房、追更日历已在 16:5x 被补上）

### 3.2 四类的落地结构（总管已定 ①+②）

```html
<!-- ① 服务挂了：带启动按钮 -->
<div class="empty unavailable">
  <b>音乐房没在运行</b>
  <span class="why">服务进程已停止，页面拿不到数据。</span>
  <button class="btn" type="button" data-act="start">启动</button>
</div>

<!-- ② 功能降级（熔断）：明确「无需操作」 -->
<div class="empty unavailable">
  <b>音乐房状态未知</b>
  <span class="why">连续探测失败，暂停检查（约 45 秒后自动重试）。</span>
  <span class="why">无需操作，会自动恢复</span>
</div>
```

**契约硬门槛（判据已实现）**：**没有动作的不可用态不合格**——每类必须有按钮，或明确写「无需操作，会自动恢复」。
