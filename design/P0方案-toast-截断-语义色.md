## §A · P0-② toast 无回看

### A.1 实测现状（8 个页面，4 种实现，11 种停留时长）

| 页面 | 签名 | 停留 | 备注 |
| --- | --- | --- | --- |
| 五五客厅 | `toast(msg)` | 2400ms | **没有错误样式**，错误和成功长得一样 |
| 书房 | `toast(msg, bad)` | 3200ms | 另有 `toast2`（第二套） |
| 媒体库 | `toast(msg, err)` | 2400ms | 参数名 `err` |
| 投屏 | `toast(msg, kind)` | bad 4200 / 其它 2600 | 参数是字符串 `'bad'/'good'` |
| 相册/笔记库/下载中心/追更日历 | `toast(msg, err)` | 2400ms（其中 1 处 6000） | 与媒体库同源 |

**停留时长实测分布：1200 / 1300 / 1600 / 1800×2 / 2200 / 2400×6 / 3000×2 / 3200 / 6000。**
⇒ 同一个失败提示，在不同房间存在时间差 **5 倍**（1200 vs 6000）。

**调用签名不兼容**：`五五客厅` 单参 10 处、双参 0 处；`投屏` 双参 16 处。参数语义三种（`bad` / `err` / `kind='bad'`）。

### A.2 失败长相（用户实际遭遇）

1. 点「移出追更」失败 → 右下角红字 2.4 秒 → 消失。
2. 用户没看清，**没有任何地方能再看到这句话**。
3. 再点一次 → 又失败 → 同样的字又闪一遍。用户以为是「第一次没点上」。
4. 连续失败 3 次后，用户会认为「这功能时好时坏」，而不是「它坏了」。

**核心缺陷不是「停留短」，是「消失后不可追回」。** 只要不可追回，把 2.4s 改成 6s 也只是延后同一个问题。

### A.3 契约（三条，缺一不合格）

**A.3-1 统一出口 + 统一签名**

```js
// 唯一签名。全站 8 个页面共用一份，放在 public/assets/feed.js
Notify.show(message, { tone: 'error' | 'ok' | 'info', sticky?: boolean, key?: string })
```
- `tone` 必须显式传，**不提供默认值**——避免「错误被当成成功」（五五客厅现在就这个问题）。
- `key` 相同的消息不重复堆叠，只更新计数（防「连点 3 次 → 3 条一样的话」）。
- 返回值 `{ id, dismiss() }`，供调用方在成功时主动撤掉。

**A.3-2 停留时长按 tone 固定，不再由各页自定**

| tone | 停留 | 理由 |
| --- | --- | --- |
| `ok` / `info` | **2000ms** | 成功不需要回看 |
| `error` | **不自动消失**（`sticky: true` 默认） | 失败必须可回看 |

**A.3-3 有「最近消息」入口（回看通道）**

- 位置：每个房间页的页脚区域固定一个 **`消息` 按钮**，仅当存在未读 error 时显示角标数字。
- 点开是一个列表：时间 + 页面 + tone + 完整文本 + `复制` 按钮。
- 只在内存保留**最近 20 条**，刷新页面即清空（不落盘，避免隐私与体积问题）。
- 空态文案：`还没有失败记录`。

**判据（可测）**：
```
1. 制造一次失败 → 页面存在「消息」按钮且角标=1
2. 等 10 秒（原 toast 已消失）→ 点「消息」→ 列表里能读到那条完整文本
3. 复制按钮 → 剪贴板内容 = 原文
4. 成功操作 → 不产生 error 记录、角标不增加
5. 快速连点失败 3 次（同 key）→ 列表只有 1 条，但带「×3」计数
```

### A.4 失败长相（修复后仍可能出现的三种坏结果）

| 坏结果 | 为什么坏 | 判据 |
| --- | --- | --- |
| 「消息」按钮常在，但列表永远空 | 用户以为有记录，点开什么都没有，比没有按钮更坏 | 无 error 时按钮不显示 |
| 把 error 也变成 sticky 常驻右下角 | 遮挡内容，且多条重叠 | 同时最多 1 条 toast，其余进列表 |
| 记录被落盘到 localStorage，越积越多 | 体积与隐私 | 刷新后清空，条数 ≤ 20 |

### A.5 退役路径

若「消息」按钮一时做不出来，**最小可交付**是：error 改为 `sticky`（不自动消失），用户手动点 `×` 关闭。
这条比现状好（可回看到用户主动关掉为止），但它仍然「关掉就没了」——所以只是降级，不算完成。

## §B · P0-③ 列表截断不告知

### B.1 实测：27 处 `slice(0,N)`，真正需要提示的只有 2 处（不是 4 处）

我逐行看了全部 27 处。产品管家说「4 处需提示」，其中包括 `书房:920` 书架 20 本——**但总管核实书架当前 0 本，且 `shelfCount` 显示真实总数**，属条件性风险。正确清单：

| 位置 | 截断 | 性质 | 需提示？ |
| --- | --- | --- | --- |
| **媒体库:248** `watched.slice(0,5)` | 5 | **把截断后的长度当总数上报**（`:251` 用 `watched.length`） | **是，P0** |
| **五五客厅:730** `todos.slice(0,5)` | 5 | 静默丢第 6 条起，无任何提示 | **是，P0** |
| 书房:920 `S.shelf.slice(0,20)` | 20 | `shelfCount` 已显示真实总数；仅 >20 本时卡片数 < 总数 | 是，但条件触发（P2） |
| 笔记库:230 `tags.slice(0,14)` | 14 | 标签云，超出属正常设计 | 否 |
| 相册:371 `slice(0,8)` | 8 | 是 `toTimeString()` 取时分秒，**不是列表** | 否（误报） |
| 下载中心:279 `slice(0,60)` | 60 | URL 文本截断 | 否 |
| 书房:920 之外 6 处 | 20/24/26/6/80/1200 | 字符串/标题截断 | 否 |

**注意 `相册:371` 是我上一版报错的**：`new Date().toTimeString().slice(0,8)` 是取时间，不是截断列表。已剔除。

### B.2 一类最严重的：*报错的那个数*

`媒体库.html:248-251`
```js
watched = watched.slice(0, 5);                                    // 截断
$('#continueCount').textContent = watched.length + ' 部在看';      // 报截断后的数
```
12 部在看 → 界面写「5 部在看」。**这不是少显示，是显示错误。** 优先级高于「没提示」。

### B.3 契约

**B.3-1 计数必须用截断前的长度**

```js
const total = list.length;              // 先存总数
const shown = list.slice(0, CAP);       // 再截断
label.textContent = `${total} 部在看`;   // 报总数
```
判据：造 12 条数据 → 界面必须显示「12」，而列表最多画 5 个。

**B.3-2 截断时必须给「还有 N 条」+ 出口**

文案规范（统一一个句式，全站不得混用其它写法）：

```
还有 7 条 · 查看全部
```
- `N = total - shown`，**必须为正整数才显示**，`N=0` 时整行不渲染。
- `查看全部` 是链接/按钮，必须真的能展开剩余内容（或跳转到完整列表页）。
- **禁止**：`更多`、`展开`、`...`、`查看全部 >`（不带 N 的写法一律不合格，因为用户不知道还有多少）。

**B.3-3 两种不可用的情况**

| 场景 | 处理 |
| --- | --- |
| 没有「全部」页面可跳 | 就地展开（列表高度增长），`还有 N 条` 变成 `收起` |
| 数据源本身只返回 5 条（后端已截断） | 前端无从判断 ⇒ **必须由后端在响应里带 `total` 字段**，否则标「未取证」不得假定完整 |

**判据（可测）**：
```
1. 造 12 条 → 列表显示 ≤5 条，且出现「还有 7 条 · 查看全部」
2. 计数显示 12（不是 5）
3. 点「查看全部」→ 能看到第 6 条
4. 造 3 条（不足上限）→ 不出现「还有」行
5. 造 0 条 → 走空态，不出现「还有」行
```

### B.4 失败长相

| 坏结果 | 判据 |
| --- | --- |
| 「还有 0 条」照常显示 | N≤0 时整行不渲染 |
| 「查看全部」点了没反应 | 点击后可见条数必须增加，或路由变化 |
| 后端没有 total，前端硬编 `还有 N` | 必须标「未取证」，不许猜 |

### B.5 退役路径

若「查看全部」需要新页面/新接口，**最小可交付**：只做 B.3-1（计数用真实总数）+ B.3-2 的文案但不给按钮（`还有 7 条`）。
这条能消除「显示错误」，但不给用户出口——属于**半完成**，要写进攻克表。

## §C · P1-④ 语义色与房色分离（我直接改 token，已算好）

### C.1 实测冲突（ΔE2000 感知色差，<10 人眼难分）

| 语义色 | 现色 | 最近房色 | ΔE | 判定 |
| --- | --- | --- | --- | --- |
| `--warn` | `#d6a05e` | `--book` `#d6a05e` | **0.00** | 完全相同 |
| `--warn` | `#d6a05e` | `--cast` `#e0a46e` | **4.23** | 几乎相同 |
| `--danger` | `#dd7768` | `--music` `#dd7768` | **0.00** | 完全相同 |
| `--ok` | `#7fbb8c` | `--library` `#9cac69` | 11.70 | 偏近 |

**另外发现两组房色自身也撞**（与语义色无关，但同样是「两个房间分不清」）：
```
--book ↔ --cast      ΔE=4.23
--download ↔ --photos ΔE=11.16
```

### C.2 采用方案 A：**只改 3 个语义色，十个房色一个不动**

理由：房色是品牌资产（规范里逐间写死），改房色影响大、且书房的暖黄是它的识别特征。语义色属于"状态信号"，本就该服从信号清晰度。

| Token | 现值 | 新值 | 对最近房色 ΔE | 对 `--bg` 对比 | 结论 |
| --- | --- | --- | --- | --- | --- |
| `--warn` | `#d6a05e` | **`#d8b83c`** | 13.49（book） | 10.08 ✅ | 琥珀金，更"警告" |
| `--ok` | `#7fbb8c` | **`#4fb583`** | 14.40（download） | 7.69 ✅ | 青绿，与暖色系拉开 |
| `--danger` | `#dd7768` | **`#de4217`** | 14.34（music） | 4.55 ✅ | 朱红，仍在红色语义内 |

**语义色三者互距**：`warn↔ok` 31.25 / `warn↔danger` 40.95 / `ok↔danger` 62.17 —— 全部 ≥14，状态之间不会混淆。

**约束说明**：我加了两条硬约束，否则数学最优解会破坏调性——
1. 饱和度 ≤82%（否则会选出 `#f40101` 纯红，在暖黑底上刺眼）
2. `--danger` 色相必须在 350°–16° 且 L∈[44..62]（必须仍是"红"，不能靠挪到玫红来凑 ΔE）

### C.3 只改 token 是**不够的**——必须先清掉 35 处硬编码十进制

这是本方案最大的坑。同一批颜色在 CSS/HTML 里被写成了十进制 `rgba()`：

| 旧十进制 | 出现 | 新十进制 |
| --- | --- | --- |
| `rgba(214,160,94,α)` (warn) | **15 处**（书房 10 / 五五客厅 2 / 相册 2 / 下载中心 1） | `rgba(216,184,60,α)` |
| `rgba(221,119,104,α)` (danger) | **15 处**（投屏 5 / 媒体库 2 / 五五客厅 2 / 书房 1 / 下载中心 1 / room.css 2 / legacy-shell 1 / vod-recs 1） | `rgba(222,66,23,α)` |
| `rgba(127,187,140,α)` (ok) | **5 处** | `rgba(79,181,131,α)` |

**⚠️ 其中 2 处 `rgba(221,119,104,…)` 不是 danger，是 music 房色**，替换会改错：
```
public/五五客厅.html:240  .room-row[data-id="music"]{--a:var(--music);--soft:rgba(221,119,104,.13);--edge:rgba(221,119,104,.38)}
public/assets/legacy-shell.css:174  body[data-room="music"]{--ww-a:#dd7768;--ww-soft:rgba(221,119,104,.14);--ww-edge:rgba(221,119,104,.34)}
```
⇒ **机械 sed 替换会把音乐房的柔光色改掉**，房间视觉全变。必须逐条按语义替换。

判定方法：看选择器里有没有 `data-id="music"` / `data-room="music"` / `--ww-a:#dd7768`——有就是房色，跳过。
