# toast 三态非颜色编码 · 契约补丁 Rev3

> 取数时刻：2026-11-22 18:40 · 输入 `public/assets/toast.js` + `public/assets/room.css`
> 触发原因：`info` 补上后，三态**只靠颜色区分**，我的三条审美判据里「去色测试」不合格。

## 一、实测：现在三态在去色后分不出来

背景色 `rgba(14,17,14,.96)`，三态文字与边框合成后：

| 态 | 文字色 | 灰度亮度 Y | 边框（合成后） |
|---|---|---|---|
| `info` | `#efe9dd`（继承 `--ink`） | 0.8185 | `(77,77,72)` |
| `good` | `#c4e4cb` | 0.7153 | `(43,91,67)` |
| `err` | `#f0b3a9` | 0.5363 | `(108,39,18)` |

**文字两两对比度（WCAG 相对亮度比）：**

```
info vs good : 1.13   ❌
info vs err  : 1.48   ❌
good vs err  : 1.31   ❌
```

**边框两两对比度：**

```
info vs good : 1.08   ❌   ← 最差的一对
info vs err  : 1.28   ✅
good vs err  : 1.38   ✅
```

判据取 **1.5**（低于此值在 12px 字号下肉眼基本不可分，且色盲用户完全不可分）。

**只调亮度救不回来**：我把 `info` 压到 `#c9c2b4` 试过，最好的一对也只有 1.31。
颜色这一维度已经用尽 —— 必须像 `.empty` 三态那样**加结构维度**。

## 二、根因：同类问题用了两套语言

`.empty` 三态当初就是按「不靠颜色」设计的（`room.css:195-236` 注释写明）：

| 态 | 边框样式 | 对齐 | 装饰 | 按钮 |
|---|---|---|---|---|
| 空 | `dashed` | 居中 | 无 | 无 |
| 出错 | `solid` | 左对齐 | 左侧 3px 竖条 | 重试 |
| 不可用 | `dotted` | 左对齐 | 顶部 3px 横条 | 动作 |

**四维同时不同，灰度与色盲下都能分。** 而 toast 三态只有 `border-color` + `color` 两个属性，
且全是颜色 —— **同一个产品里，「三态怎么区分」有两套语言，这是契约不一致，不是实现疏忽。**

## 三、契约：toast 三态必须四维不同（与 `.empty` 同构）

toast 是 12px 单行浮层，没有空间做对齐/竖条，可用的非颜色维度只有**前置符号**与**边框虚实**。
按可用性排序取三条：

| 态 | 前置符号 | 边框样式 | 可点击 | `::after` |
|---|---|---|---|---|
| `info` | `·`（中点，最轻） | `dashed` | 否 | 无 |
| `good` | `✓` | `solid` | 否 | 无 |
| `err` | `!` | `solid` 2px | 是 | `· 点此关闭` |

**为什么是这三个符号**：ASCII/全角在 12px 下都能渲染；形状差异在灰度下最大（点 / 勾 / 竖线）；
不依赖 emoji（避免平台字体差异，且 emoji 自带颜色会破坏去色测试）。

**为什么 `err` 边框加粗到 2px**：`err` 是唯一「用户必须做点什么」的态，
加粗在灰度下是最强的形状信号；同时它是唯一可点击的，`cursor:pointer` + `::after` 已有第二重提示。

## 四、验收判据（三条，全部可自动测）

```
① 去色可分：三态文字两两对比度 ≥ 1.5，或（文字不足时）前置符号存在且三者不同
② 缩小可分：缩到 50%（即 6px 等效）时，前置符号仍能区分（符号是字形不是细节）
③ 不依赖 emoji：content 里不含 U+1F300–U+1FAFF 区间字符
```

**失败长相**：
- 三态截图去色后肉眼分不出 → ①不过
- 用 emoji 做符号 → ③不过（且 macOS/Android 渲染不同）
- 只有 `err` 有符号、另两态没有 → 那 `info` 与 `good` 仍不可分 → ①不过

## 五、落地（属前端文件，我只出契约）

```css
/* toast.js 的 ensureStyle() 里追加，或 room.css 的 toast 段 */
.toast.info{border-color:rgba(239,233,221,.28);border-style:dashed}
.toast.info::before{content:"· ";opacity:.6}
.toast.good::before{content:"✓ "}
.toast.err{border-width:2px}
.toast.err::before{content:"! ";font-weight:700}
```

**注意**：`toast.js` 的 `t.textContent = text` 会把 `::before` 的内容**保留**（伪元素不在 textContent 里），
所以不需要改 JS —— 这条我已确认，不需要前端改逻辑。
