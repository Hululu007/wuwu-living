# S4 / S1「不可用」态定义（产品侧交付，可判定）

> 产品管家 · 2026-11-22
> 依据：本项目实测的失败形态（不是通用分类）。每条 = 触发条件 + 判据 + 用户原话 + 可做什么。

---

## 0. 先说三条必须遵守的边界

1. **本项目没有「额度用完」这一类。** 实测：`grep -rlnE '额度|配额|quota|余额|积分|剩余次数' public/ lib/ config/` → **0 个文件命中**；9 个视频采集站无 key、无额度；音乐走 `api.fanxing.life` 免费解析。**凭空加「额度用完」会让前端写一个永远不会出现的状态。** 用「上游能力不可用」替代（见第 4 条）。
2. **「无权限」在本项目只有三种真实形态**，都已被后端写成中文原因（见第 1 条），前端不要另造。
3. **断网与服务不可达必须分开**，浏览器侧可判定：`navigator.onLine === false` → 断网；`onLine === true` 且 fetch 抛 `TypeError` → 服务不可达。

---

## 1. 无权限（本机已发生，后端已有原因文案）

| # | 触发条件（可判据） | 判据来源 | 用户原话 | 可做什么 |
|---|---|---|---|---|
| 1.1 | 相册索引 `~/Pictures/Photos Library.photoslibrary` 时 `EPERM` | `lib/photos.mjs:174/184` `skipped[].reason` | **「系统相册库受保护，未索引」** | 无操作，只说明。这是 macOS 权限，不是故障 |
| 1.2 | 投屏 `adb devices` 返回 `unauthorized` | `lib/cast.mjs:338` 状态机含 `unauthorized` | **「手机没授权调试：请插 USB → 在手机上点『允许 USB 调试』」** | 给一次「重新检测」按钮 |
| 1.3 | 投屏 `adb devices` 无设备 | `lib/cast.mjs:443` 现成文案 | **「没有检测到手机：插 USB，并在手机上允许 USB 调试」** | 给「重新检测」按钮 |

**渲染要求**：这三种都属「可恢复/不可恢复」混合，**不要用红色错误样式**（红色留给真故障），用中性提示 + 可选动作。

## 2. 服务挂了（三种必须区分，判据完全不同）

浏览器侧可用三种不同信号区分，实测依据：

| # | 触发条件 | 浏览器可见信号 | 用户原话 | 可否自动重试 |
|---|---|---|---|---|
| 2.1 | **连接被拒**：端口无监听（进程死了/没起） | `fetch` 抛 `TypeError`，耗时 **<50ms**（实测 `code=000 t=0.0003s`） | **「服务没在运行」** | ✅ 可给「启动」按钮（`POST /api/apps/<id>/start`） |
| 2.2 | **挂起/超时**：端口在听但不回包（今天音乐房就是这形态） | `AbortController` 触发（**不是** TypeError），耗时 = 你的超时值（实测 `t=3.0s`） | **「服务没有响应，正在等它恢复」** | ✅ 自动重试 2 次后再报；**不要立刻判死** |
| 2.3 | **非 2xx**：服务活着但返回错误 | `res.ok === false`，有 `res.status` | **「服务出错了（HTTP {status}）」** | ❌ 不自动重试，显示原因 + 重试按钮 |

**这三条必须用不同文案**，因为用户能采取的动作不同：
- 2.1 → 可以启动
- 2.2 → 只能等
- 2.3 → 需要看原因

**今天的真实教训**：音乐房假死时，`8890/music/` 靠 `STATIC_PAGE_TTL=5s` **始终返回 200**，用户看到「页面打开了、点歌没反应」。这是 2.2 形态被页面缓存掩盖。**所以 2.2 的判据不能只看页面，要看页面内数据接口。**

## 3. 离线（两种，页面必须用不同的话）

| # | 触发条件 | 判据 | 用户原话 |
|---|---|---|---|
| 3.1 | **浏览器断网** | `navigator.onLine === false` | **「网络断了：检查 Wi-Fi / 网线」** |
| 3.2 | **局域网内服务不可达**（浏览器有网，但客厅/房间服务连不上） | `onLine === true` 且 fetch `TypeError` | **「连不上客厅：服务可能没启动」** |

**为什么必须分开**：3.1 用户该去修网络，3.2 用户该去启动服务。**同一句话会让用户做错动作。**
**判据可实现，但前端当前一处都没做**（我先前写「已引用 4 处」是误报，已更正）：
```
grep -rn 'navigator.onLine' public/        → 0 处
grep -rn 'AbortController' public/         → 0 处
grep -rn 'instanceof TypeError' public/    → 0 处
```
（先前误判的来源：`五五客厅.html:966/974/987/988` 的 `online` 是统计在线房间数的**局部变量**，与 `navigator.onLine` 无关。）
⇒ 3.1/3.2 要落地，前端需**新增**三样：`navigator.onLine` 判定、`AbortController` 超时、`TypeError` 分支。这是新增工作量，不是复用。

## 4. 上游能力不可用（替代「额度用完」，本项目真实存在）

| # | 触发条件 | 判据来源 | 用户原话 | 可做什么 |
|---|---|---|---|---|
| 4.1 | 音乐完整曲解析失败，回落 11 秒试听 | `server.mjs:268` 注释 + `kuwoFullUrl()` 失败分支 | **「只找到 11 秒试听（完整曲解析没成功）」** | 换源重试 |
| 4.2 | 豆瓣刮削未命中 | `lib/library.mjs` `matched=None` | **「没匹配到豆瓣条目，只显示本地信息」** | 无操作（本机无 key，属正常） |
| 4.3 | 追更源被抓取拦截 | `lib/calendar.mjs` `failReason` | **「抓取失败：被站点风控拦截（上次成功：{时间}）」** | 换源 |
| 4.4 | 磁力 DHT 拿不到节点 | 页面已实现 | **「等待 DHT 节点」** | 无操作 |

**这四条都属于「功能降级但仍可用」**，不要用错误红，用琥珀/中性色 + 说明。

## 5. 六态归属（S4 落地判据）

| 状态 | 判定条件（一条即可） | 样式 | 必带元素 |
|---|---|---|---|
| 空 | 接口 200 且数据数组长度 = 0 | 中性 | 一句「还没有 X」+ 一个创建入口 |
| 正常 | 接口 200 且数据非空 | — | — |
| 加载中 | 请求已发出、未返回 | 骨架/转圈 | 不得超过 **8 秒**仍无结果 |
| 出错 | 2.3（非 2xx）或 2.1（被拒） | 红 | 原因 + 重试按钮 |
| 超量 | 列表被截断（`slice(0,N)` 生效） | 中性 | **「共 N 条，显示最近 M 条」**（媒体库 `continueCount` 已按此修） |
| 不可用 | 2.1 / 2.2 / 3.1 / 3.2 / 第 1、4 条 | 中性或琥珀 | **原因 + 一个可执行动作** |

**硬要求**：不可用态**必须**包含「用户能做什么」。「服务没在运行」不带启动按钮 = 不合格。

## 6. 失败长相（若不做，用户会看到什么）

| 档 | 现象 |
|---|---|
| 最坏 | 页面 200 但功能全哑（今天音乐房），用户以为「这功能就是坏的」 |
| 常见 | 断网和服务挂了都说「连接失败」，用户去重启路由器 |
| 最阴 | 转圈 8 秒后回到空态，用户以为「本来就没有内容」 |

---

## 7. 退役路径
- 若只做一条：**先做 2.2（挂起）**——它是今天唯一真实发生且被页面缓存掩盖的形态。
- 若前端来不及：**至少把 `degraded:true` 消费掉**（后端已在 `/api/status` 返回，前端当前 **0 处引用**），显示「状态未知」而不是假装「已停止」。

## 8. 可测验收判据（每条可跑）

```bash
# 2.1 连接被拒：杀 8811 → /music/ 必须给「服务没在运行 + 启动按钮」，不许空白
# 2.2 挂起：iptables 或黑洞端口模拟 → 必须 8 秒内出「没有响应」，不许无限转圈
# 3.1 断网：Chrome DevTools 离线 → 必须说「网络断了」，不许说「连不上客厅」

```

## 9. 前端落地清单（按现有代码缺口，最小改动）

| 要做的 | 现在 | 改动点 | 判据 |
|---|---|---|---|
| 消费 `degraded` | 后端 3 处、前端 **0 处** | `五五客厅.html` `doorData()` 里读 `a.degraded`，label 显示「状态未知」 | `grep -c degraded public/五五客厅.html` ≥ 1，且断开上游时门牌显示「状态未知」而非「未启动」 |
| 区分被拒 / 挂起 | `catch` 不分类（`书房.html:918` 一律「没连上」） | 统一 fetch 包装：`TypeError`→被拒；`AbortError`→挂起；`!ok`→HTTP 错 | 三种故障各造一次，文案必须三样不同 |
| 断网判定 | `navigator.onLine` **0 处** | `五五客厅.html` 顶部加 `online/offline` 监听 | 断网时文案含「网络断了」；服务挂时不含这句 |
| 超时上限 | 无 `AbortController`（**0 处**） | 所有房间数据请求加 8s 超时 | 挂起场景 8s 内必须出「没有响应」 |
| 不可用态渲染 | 8/8 房缺 | 每房一个 `.unavailable` 区块（原因 + 动作按钮） | 每房 6 态各截图一张 |

**优先级（按今天真实发生频率）**
1. **消费 `degraded`** —— 后端已给，前端白拿，改动最小
2. **区分被拒 / 挂起** —— 今天音乐房就是挂起被当成了「没连上」
3. **断网判定** —— 让用户别去重启路由器
4. **不可用态渲染** —— 8 房铺开，工作量最大
