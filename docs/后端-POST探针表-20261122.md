# POST-only 路由探针表（后端管家 · 2026-11-22）

给测试管家的 `health-audit.mjs` 用。**目的**：把 9–10 条「源码有、GET 打 404」的路由从「未取证」变成可判定的 PASS/FAIL。

## 一、结论先行：它们全都不是死路由

实测环境：独立实例 `PORT=8897 WUWU_RUNTIME_DIR=/tmp/ww-probe-rt`（**不碰真实 runtime，写入落在临时目录**）。

| 路由 | 方法 | 探针 body | 期望码 | 实测 | 实测 message |
|---|---|---|---|---|---|
| `/api/book/ensure` | POST | `{}` | 200 | **200** | Reader 未运行；客厅不会启动它 |
| `/api/book/search-start` | POST | `{}` | 400 | **400** | 缺少书名或作者 |
| `/api/book/shelf/add` | POST | `{}` | 400 | **400** | 缺少有效的书籍地址 |
| `/api/book/shelf/remove` | POST | `{}` | 400 | **400** | 缺少书籍地址 |
| `/api/book/open` | POST | `{}` | 502 | **502** | 打开这本书失败：这本书没有可用的书源 |
| `/api/book/chapter` | POST | `{}` | 502 | **502** | 取正文失败 |
| `/api/book/progress` | POST | `{}` | 502 | **502** | 缺少书籍或章节进度 |
| `/api/start` | POST | `{}` | 400 | **400** | 没有这个项目 |
| `/api/stop` | POST | `{}` | 400 | **400** | 没有这个项目 |
| `/api/reader/open` | POST | `{}` | 403 | **403** | 客厅不再打开 Reader（有意封禁） |

**判据**：空 body POST 只要返回**任何业务错误报文**（400/403/502 且 message 是中文业务话术），就证明**路由已注册且被执行**，不是死路由。

## 二、真·死路由的唯一特征

```
POST /api/book/nonexistent-xyz   → 404  {"ok":false,"message":"没有这个页面"}
GET  /api/totally-fake-route     → 404  {"ok":false,"message":"没有这个页面"}
```

**唯一判据是报文里的字符串 `没有这个页面`。** 不能只看 404 状态码：
- 真死路由：`404` + `没有这个页面`（hub 兜底）
- 路由存在但参数不对：`400/403/502` + 中文业务 message
- 路由存在但方法不对：`405` + 业务 message

## 三、探针怎么跑（给审计器）

```bash
for p in ensure search-start shelf/add shelf/remove open chapter progress; do
  code=$(curl -s -o /tmp/p.json -w '%{http_code}' -m 8 -X POST \
    "http://127.0.0.1:8890/api/book/$p" -H 'content-type: application/json' -d '{}')
  msg=$(python3 -c "import json;print(json.load(open('/tmp/p.json')).get('message',''))")
  case "$code" in
    404) grep -q '没有这个页面' /tmp/p.json && echo "FAIL 死路由 $p" || echo "PASS $p" ;;
    200|400|403|405|502) echo "PASS $p  ($code $msg)" ;;
    *) echo "UNVERIFIED $p  ($code)" ;;
  esac
done
```

## 四、两条纪律

1. **不要在生产实例上跑写接口探针**。`shelf/add`、`progress` 会写 `runtime/book_shelf.json`。要跑就起 `WUWU_RUNTIME_DIR=/tmp/...` 的隔离实例（本表就是这么测的）。
2. **`/api/start` `/api/stop` 是例外**：它们操作的是**真实 launchd 服务**，即使 runtime 隔离也会真的拉/停进程。审计器里请把这些标成 `SKIP-危险`，或用 `{}`（会因"没有这个项目"直接 400 而不动任何服务）——本表实测 `{}` 是安全的。
