# 五五客厅 → 五五工作台 集成方案（D 段 · 可行性评估）

> 状态：**待审**。本文只做评估与改造点清单，**未改动工作台任何代码**。
> 撰写时间：2026-11-17 · 依据：本机实测（`workbench-src` 源码、`五五客厅` 运行实例、launchd plist、外部 app 配置）。

---

## 0. 结论

**不做独立 APK，并进五五工作台。** 工作台已有 Java WebView 壳 + 签名 + 版本号 + Gitee releases 发布链，再开一个 APK 等于重复造轮子，还要多维护一套 keystore 与更新通道。

但「并进去」不等于「加个链接」——有 **3 个会直接导致白屏或播不了** 的硬点（明文 http、HLS、返回键）和 **1 个安全缺口**（客厅无鉴权），必须在动手前定方案。本方案逐条给出改造点与验证方法。

## 2. 集成架构（推荐 A：iframe 嵌入）

工作台加一个「五五客厅」模块页（仍是 SPA 内的一页），页内放**全屏 iframe**，`src` 指向客厅地址（可配）。

**为什么用 iframe 而不是把客厅当独立 WebView 页面 loadUrl：**
- 工作台 SPA 是 `file://` 页面，若直接 `fetch('http://192.168.x.x:8890/api/...')`，Origin 为 `null` → 需要客厅侧补 CORS 头，等于给自己开一个跨源口子；
- iframe 内每个客厅页面自身同源，**零 CORS 改造**，且客厅内部路由（`/book/` → `/api/book/open`）本来就是同源相对路径，`src` 换 base 即可；
- 客厅后续加鉴权时，只需要 iframe 首屏带一次 token query，cookie/query 在同源 iframe 内自然延续。

**方案 B（备用）**：工作台直接 `loadUrl("http://192.168.x.x:8890/")` 铺满全屏，SPA 作为「去客厅」按钮。优点是最快最稳（不受 file:// CORS 影响），缺点是客厅一旦连不上就是白屏，且工作台自己的模块（今日/考研/写作）与客厅来回切要靠两个入口。**建议 A 为主、B 作为 A 的降级兜底**（连不上时给出「打开浏览器/重试/改地址」三按钮）。

## 4. 三个硬点，逐个给结论

### 4.1 明文 http（`usesCleartextTraffic`）
- 现状：Manifest 没有该属性，targetSdk 34 → **必然加载失败**（`ERR_CLEARTEXT_NOT_PERMITTED`）。
- 结论：必须开。建议用 `network_security_config.xml` 精确放行内网网段，而不是全局 `true`（全局 true 会让 App 里任何 http 都可跑，安全面变大）。
- 验证：真机访问 `http://10.18.246.60:8890/api/ping` 应 200；访问公网 http 站点应仍被拦（证明是精确放行而不是全局放开）。

### 4.2 HLS（最大的坑，但不在客厅）
- 事实：客厅 `public/` 内**没有** m3u8/HLS 代码；视频房 `/vod/` 反代的是外部工程「请看」（`/Users/wuwu/D盘/项目/请看`），该工程自带 `public/hls.min.js` 且以 m3u8 播放。**所以 HLS 能不能播，取决于「请看」的 hls.js 在 Android WebView(MSE) 里跑不跑得起来**，与客厅无关。
- 现状阻塞：`8900` 当前**未启动**（`lsof` 无监听），客厅 `/vod/` 走的是「暂时没开」占位页（实测 8.9ms、502，设计内）。**要验证 HLS 必须先 `vod.sh start` 起「请看」**。
- 结论与顺序：
  1. 先做 `assets/hls-verify.html` 诊断页（不外发）：检测 `MediaSource` 是否存在 → 注入 hls.js → 播一段公开 m3u8 → 打印 `readyState/error`；
  2. 通过 → 工作台直接嵌客厅 `/vod/`，无需 Java 改造；
  3. 不通过（老 WebView 无 MSE，或 hls.js 版本不兼容）→ 走 W7 的 ExoPlayer 兜底（工作量 +1 天）；
  4. **先验证再谈体验**，不要在没验证前给用户承诺「手机上能看视频」。

### 4.3 返回键
- 现状：`onBackPressed`（431–440）已判 `canGoBack()`，但客厅是 SPA（URL 不变）→ `canGoBack()` 恒 false → 用户按一下直接退出 App。
- 结论：加 W5 的 JS 桥约定（先问客厅「能不能返回」，客厅答 yes 就消费掉）。这条改动小但要和 A1 的「唯一返回入口」规则一起设计，避免又出现两个返回。

## 5. 安全缺口：客厅当前无鉴权

- 现状：`hub.mjs` 内无任何 token/cookie 会话校验，`BIND` 一旦改成 `0.0.0.0`，**同一 WiFi 下任何设备（包括访客、智能电视、IoT）都能读写**：下载接口能触发下载、日历能改、书房能删追更。
- 结论：**L2（极简 token）必须先于 LAN 暴露上线**，顺序不能反。方案：首次启动生成 32 字节 token → 写 `runtime/access-token.json`（0600）+ 终端打印一次 → 手机首次访问要求输入口令 → 写 `ww_k` cookie（`HttpOnly; SameSite=Lax`，局域网 http 无法 `Secure`，这点要如实承认）。
- 已知局限（不吹）：局域网 http 下 cookie 无法 `Secure`，同网段抓包理论上可截获 token；家里场景可接受，公网穿透场景必须再加一层（反代 TLS 或 tailscale）。

| 风险 | 影响 | 概率 | 应对 |
|---|---|---|---|
| Android WebView 无 MSE / hls.js 不兼容 | 视频不能播（最大体验缺口） | 中 | W7 诊断页先验；不过则 ExoPlayer 兜底 |

| 手机与 Mac 不同网段（`10.18.x` vs 访客网络） | 扫描扫不到 | 高 | 扫描同时支持「手工输入」与「100.x 穿透地址」两条路 |
