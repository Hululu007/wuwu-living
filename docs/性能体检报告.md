## 1. 首屏到可交互（4 个主力页，冷 / 热两组）

口径：`fetch` 计时（TTFB 与总耗时）+ 响应字节 + HTML 内 `<script>`/`<link>` 计数；阻塞脚本 = 无 `async`/`defer` 的 `<script>`（内联脚本默认阻塞）。
冷 = 进程内首次请求；热 = 紧随第二次、第三次。`cache-control: no-store/no-cache` 下浏览器**不缓存**，热命中只反映服务端进程内缓存壳，不代表浏览器二次访问。

| 路径 | 字节 | 冷 total ms | 热1 ms | 热2 ms | script 总数 | 阻塞脚本 | CSS link | 缓存头 | ETag / Last-Modified |
|---|---:|---:|---:|---:|---:|---:|---:|---|---|
| `/` | 55,130 | 51.82 | 5.80 | 3.86 | 1（内联） | 1 | 0 | `no-store` | 无 / 无 |
| `/book/` | 71,341 | 4.19 | 4.20 | 9.64 | 3（全内联） | 3 | 0 | `no-store` | 无 / 无 |
| `/library/` | 21,785 | 15.56 | 3.98 | 5.49 | 2（内联，含注入的 embed-flag） | 2 | 1 | `no-store` | 无 / 无 |
| `/music/` | 103,044 | 37.99 | 3.52 | 12.83 | 3（全内联） | 3 | 0 | `no-cache`（透传上游） | 无 / 无 |

要点：
- 四个页面**没有外链 JS**，脚本全是内联；阻塞脚本即全部内联脚本数量。首屏 JS 不经过独立文件缓存，随 HTML 一起被 `no-store` 挡掉。
- 冷请求抖动较大（`/` 51.82ms、`/library/` 15.56ms、`/music/` 37.99ms），与进程事件循环 / 上游探测叠加有关；热请求 p50 3.5–5.8ms，服务端处理本身很轻。
- 所有 HTML 响应均无 ETag / Last-Modified；浏览器刷新或二次进入都会重新拉全量 HTML。

## 2. `/music/` 92KB 每请求重写（重点项）

### 2.1 实测分布（N=30 连发；另补 5 个 TTL 过期 miss 样本）

| 来源 | 字节 | p50 ms | p95 ms | max ms | Cache-Control | ETag | Last-Modified |
|---|---:|---:|---:|---:|---|---|---|
| 上游直连 `127.0.0.1:8811/` | 92,728 | 24.42 | 30.05 | 34.40 | `no-cache` | 无 | 无 |
| 代理 `8950/music/`（5s 壳内连发） | 103,044 | 3.25 | 5.54 | 6.36 | `no-cache`（透传上游） | 无 | 无 |
| 代理 miss（每发前等 5.6s 让 5s 壳过期） | 103,044 | **33.69** | — | 87.73 | 同上 | 无 | 无 |
| 代理内存壳命中（TTL 内 10 连发） | 103,044 | 2.87 | — | 4.67 | — | — | — |
| 对照：`/api/ping` 无 body 轻路由 | — | 2.82 | — | 4.84 | `no-store` | — | — |

- 重写增量：92,728 → 103,044，**+10,316B（+11.13%）**；增量来自 `rewriteText` 前缀改写与外壳注入（`hub.mjs` L1747–1756）。
- 上游首页两次抓包 `diff = 0`（无内联时间戳 / 易变 JSON，封面与榜单走前端 `/api/` 拉取），**外壳是静态的，适合长缓存 + 条件请求**。
- 现有代理壳：`staticPageCache`（`hub.mjs` L73）TTL 仅 **5000ms**（L74），且只缓存重写后 body；下发头仍透传上游 `no-cache`，**没有生成 ETag，也没有处理 `If-None-Match`**。5s 外每次都回上游重生成 + 全量重写 + 103KB 下行。

### 2.2 加缓存后预期收益（实测依据，非估算拍脑袋）

- 重复访问：miss p50 33.69ms / 103,044B → 命中壳 2.87ms；条件请求 304 无 body，耗时参照轻路由 p50 2.82ms（304 只做头判定 + 写头，不构造 Buffer、不 `JSON.stringify`）。
- 每次重复访问省：下行 103,044B、上游重生成 ~24ms、代理一次全量 `rewriteText` + Buffer 构造。
- 风险与边界：封面/榜单等动态数据仍走 `/api/`，HTML 外壳缓存不影响数据新鲜度；若上游外壳将来内联易变数据，ETag 基于重写后 body 哈希，body 变了 ETag 自动变，304 不会误命中。

### 2.3 `hub.mjs` 精确补丁建议（由组织者落地，本轮未改）

**现状定位**

- L73–74：`const staticPageCache = new Map(); const STATIC_PAGE_TTL = 5000;`
- L1678–1684：music 首页 GET `/` 先查内存壳，命中直接 `res.writeHead(cached.status, cached.headers); res.end(cached.body);`
- L1720–1730：上游响应头逐条透传（`location` 改前缀）；上游给的 `no-cache` 被原样下发。
- L1758–1763：重写后构造 `buf`、重算 `content-length`，L1760–1762 把 body 写回壳。

**补丁 A：延长壳 TTL + 壳条目带 ETag（L73–74 附近）**

```js
const staticPageCache = new Map();
const STATIC_PAGE_TTL = 5 * 60 * 1000; // 5s → 5min；外壳静态，封面走 /api/

// 零依赖短哈希（FNV-1a 32bit），用于生成弱 ETag
function bodyEtag(buf) {
  let h = 0x811c9dc5;
  for (let i = 0; i < buf.length; i++) { h ^= buf[i]; h = Math.imul(h, 0x01000193); }
  return 'W/"' + buf.length + '-' + (h >>> 0).toString(36) + '"';
}
```

**补丁 B：命中分支加条件请求 304（替换 L1678–1684）**

```js
if (id === 'music' && req.method === 'GET' && rest === '/') {
  const cached = staticPageCache.get(id);
  if (cached && Date.now() - cached.at < STATIC_PAGE_TTL) {
    const inm = req.headers['if-none-match'];
    if (inm && inm === cached.etag) {
      res.writeHead(304, {
        etag: cached.etag,
        'cache-control': 'private, max-age=300, must-revalidate',
      });
      return res.end();
    }
    res.writeHead(cached.status, cached.headers);
    return res.end(cached.body);
  }
}
```

**补丁 C：写壳时生成 ETag 并下发可缓存头（替换 L1760–1762）**

```js
if (id === 'music' && rest === '/' && r.status === 200) {
  const etag = bodyEtag(buf);
  outHeaders['etag'] = etag;
  outHeaders['cache-control'] = 'private, max-age=300, must-revalidate'; // 覆盖上游 no-cache
  staticPageCache.set(id, { at: Date.now(), status: r.status, headers: { ...outHeaders }, body: buf, etag });
}
```

**补丁 D（顺带，本地静态资源）：`lib/rooms.mjs` `ctx.file` L152 / L162**

现状非 `runtime/` 文件一律 `no-store`。建议对 `public/assets/` 下文件用 `st.mtime` 生成 `Last-Modified`/ETag，识别 `If-Modified-Since`/`If-None-Match` 回 304；缓存头改 `public, max-age=300, must-revalidate`（文件名无内容指纹，不宜长强缓存）。`runtime/` 下产物维持现有 `private, max-age=86400`。

> 注意：`hub.mjs` 本轮按纪律未改；以上为行号区间 + 代码片段 + 理由，供组织者落地。
