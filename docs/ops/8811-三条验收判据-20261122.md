## 固定指纹验证（总管要求写进监控）

判据：`state=running` 且 `last exit code ∉ {0, 143}` ⇒ launchd 在骗你，报 WARN。
（143 = SIGTERM，正常重启）

单测五种状态：
```
state=running lastExit=0     （正常）        → PASS
state=running lastExit=143   （SIGTERM 重启） → PASS
state=running lastExit=1     （崩溃！）       → WARN   ← 今天 8811 就是这个码
state=running lastExit=2     （异常退出）     → WARN
state=running lastExit=（空）               → PASS
```
已在 `scripts/ops-monitor.sh:87-92` 落地。

★ **诚实说明这个判据的强度边界**：它只报 WARN（exit=1），不报 FAIL。
因为 `lastExit≠0` 也可能只是上一次异常退出、当前已经恢复（如今天的 143 或修复后的正常重启）。
**真正判死靠的是独立那一条「入口存活」检查**——今天 8811 死的时候，那一项会报 FAIL。
两条必须一起看，单看任何一条都会误判。

## 修掉一个我自己引入的显示缺陷

**现象**：`ops-8811.sh` 把端口写死成 8811，用 `URL=http://127.0.0.1:8898/` 测死端口时，
旁证仍然打印「**8811 在听**」——与实际测的 8898 完全不符，是误导。

**修法**（备份 `ops-8811.sh.bak-20261122-1602-portfix`）：从 URL 里解析端口
```bash
UP_PORT="$(printf '%s' "$URL" | sed -E 's#^https?://[^:/]+:?([0-9]*).*#\1#')"
[ -z "${UP_PORT:-}" ] && UP_PORT=80
lsof -nP -iTCP:"$UP_PORT" -sTCP:LISTEN
```

**修复后对照**：
```
URL=:8898 → 端口旁证: 8898 无监听   ✅ 与实测一致
URL=:8811 → 端口旁证: 8811 在听     ✅ 回归正常
```
