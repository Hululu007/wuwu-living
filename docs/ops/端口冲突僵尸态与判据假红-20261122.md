# 端口冲突僵尸态 + 两条判据假红（2026-11-22 17:00–17:10）

## 一、真缺陷：8890 端口冲突会变成僵尸态，launchd 不会拉起

### 现场（隔离端口 19080，非项目端口）
```
占位进程 node 先监听 127.0.0.1:19080
PORT=19080 node hub.mjs            → 进程存活 state=S
curl :19080/api/status             → 200 "occupied"   ← 是占位进程在应答
hub 自身日志                        → [.. ] uncaught: listen EADDRINUSE: address already in use 127.0.0.1:19080
```

**根因链**：
1. `hub.mjs` 的 `process.on('uncaughtException')` 吞掉所有异常（只写日志，不退出）；
2. `server.listen(...)` 没有 `server.on('error')` 兜底；
3. EADDRINUSE 被吞 ⇒ 进程不退出 ⇒ `KeepAlive=1` 认为进程还在，不重启；
4. 结果：`launchctl` 显示 `state=running`，端口无人监听，日志里只有一行 uncaught。

这与寻源管家在 8811 上实测的「B 组 exit=0」是同一机制，但 8890 更糟——它是**不退出**，8811 是**以 0 退出**。

### 修法
`hub.mjs`：
```js
const FATAL_EXIT_CODES = new Set(['EADDRINUSE','EACCES','EADDRNOTAVAIL']);
process.on('uncaughtException', (err) => {
  _appendLog(...);                       // 证据照旧落持久目录
  if (err && FATAL_EXIT_CODES.has(err.code)) {
    _appendLog(...fatal...);
    process.exit(1);                     // 让 launchd 能重启
  }
});
server.on('error', (e) => { _appendLog(...); process.exit(1); });
```

### 三臂
| 臂 | 条件 | 结果 |
|---|---|---|
| 负向（修前） | PORT=19080 被占 | 进程 state=S 存活，端口被别人应答，日志一行 uncaught |
| 负向（修后） | PORT=19081 被占 | `[server.error] EADDRINUSE` → **exit=1** |
| 正向（修后） | PORT=19082 空闲 | bind ok 19ms，`/api/status` 200，进程存活 |

回滚：`cp hub.mjs.bak-addrfatal-20261122-170314 hub.mjs && launchctl kickstart -k gui/$(id -u)/com.wuwu.wuwu-living`

## 三、两条判据假红（都是我自己参数/判据写错，不是产品缺陷）

### 假红 1：`ops-watch.sh` 阈值不跟随采样数
`MIN_OK` 默认 18 是配 `-n 20` 的。我只传 `-n 3` 不传 `-m`，阈值仍是 18/3，
于是 **3 次全过也被判 DEGRADED**。判据没坏，是调用方少给一个参数却拿到红。

修法：未显式给 `-m` 时按 95% 跟随 `-n`；`-m > -n` 直接 `exit=3 判据故障`。

| 臂 | 命令 | 结果 |
|---|---|---|
| 正向 | `-n 20`（不给 -m） | 阈值 19/20，ALIVE 20/20，EXIT=0 |
| 负向（旧缺陷） | `-n 3`（不给 -m） | 阈值 3/3，ALIVE 3/3，EXIT=0（旧版必 DEGRADED） |
| 负向（矛盾参数） | `-n 3 -m 9` | `判据故障: 最少命中 9 大于采样数 3`，EXIT=3 |

### 假红 2：`ops-discipline.sh fixtures` 把浏览器调试端口当夹具
原判据：「19000-19999 有监听且无 `WUWU_RUNTIME_DIR`」一律不合规。
实测有成员用 Chrome `--remote-debugging-port=19844` 做真浏览器探针，被报「夹具不合规」，
整轮 `ops-discipline` 退 2。浏览器调试端口没有共享运行时状态可污染，不是夹具。

修法：加 `NOT_FIXTURE_RE='Google Chrome|Chromium|Microsoft Edge|Safari|firefox|playwright|chromedriver'`，
命中则「跳过」不参与 FAIL。只排除确知不是夹具的进程名，不做宽泛白名单。

| 臂 | 条件 | 结果 |
|---|---|---|
| 负向（识别力未被削弱） | 真夹具 `hangtest/srv.mjs` 占 19011 | 仍报 `警告 ... FAIL 1 个夹具不合规`，EXIT=2 |
| 正向 | Chrome 调试端口 19850 | `跳过 pid=17380 端口=19850 浏览器/调试工具调试端口，非夹具` |
