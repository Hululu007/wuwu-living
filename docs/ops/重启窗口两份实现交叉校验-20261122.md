# 重启窗口：两份实现的交叉校验（2026-11-22 16:38）

## 一、发现同类风险：同一判据两份实现

总管把「重启窗口」加进了 `health-audit.mjs`（`classifyUptime`，:977），
我之前也把它加进了 `ops-discipline.sh uptime`（`:160` 附近）。

**这正是我今天刚退役 `ops-cleanup-tmp-logs.sh` 时那个病的同一型**：
两个实现都在、单独跑都能过，但**谁生效取决于你跑哪个**。

## 二、交叉校验方法：同一时刻两侧对同一 pid 取值

不能只各自跑一次看「都通过」——必须**同一时刻**比对数值与判定。

### 第一版校验脚本失败（我的量具又错了）
```bash
grep "8811"        # ← 匹配到 3 行：端口检查、音乐服务检查、重启窗口
sed 's/.*已运行 ([0-9]+)s.*/\1/'
→ 变量里塞进整行中文，报 "operand expected"
```
**教训：`grep <端口号>` 在多功能输出里必然多命中，必须锚定行首状态词 + 端口。**

### 第二版（正确）：正则锚定 `(OK|窗口内)\s+<port>\s`
用 python 做，避免 shell 编码与字段切分问题：
```python
dl = [l for l in d.splitlines() if re.search(rf'(OK|窗口内)\s+{port}\s', l)]
hl = [l for l in h.splitlines() if f'端口 {port} ' in l and '重启窗口' in l]
```

## 三、校验结果：五个端口判定完全一致

```
端口      discipline      audit           一致?
8811    772s/已过         773s/已过         ✅
8890    NAs/窗口内         46s/窗口内         ✅
7788    73967s/已过       73968s/已过       ✅
8317    266653s/已过      266654s/已过      ✅
12010   21881s/已过       21881s/已过       ✅
```

**数值差 0–1 秒**：两次调用之间的真实时间流逝，不是判据差异。
**判定（已过 / 窗口内）五端口全部相同** —— 两份实现无分歧，当前可以并存。

（8890 那格 `NAs` 是我脚本的 `sed` 在「启动仅 Ns」格式下没抽到数字，
但**状态判定「窗口内」两侧一致**，这才是判据本身。）

## 四、顺带查清：8890 的 pid 为什么一直在变

观察期间 pid 变化：38430 → 54710 → 59219。查统一日志（权威）：

```
16:31:35  removing service: com.wuwu.wuwu-living
16:32:12  removing service: com.wuwu.wuwu-living
16:35:56  removing service: com.wuwu.wuwu-living
```

**`removing service` 是 `launchctl bootout` 留下的**，不是崩溃
（崩溃会表现为 `service inactive` 后反复 spawn 且 `last exit code ≠ 0`）。

**30 秒稳定性观察（确认已稳）：**
```
16:37:32  pid=59219  runs=2  etime=01:31
16:37:40  pid=59219  runs=2  etime=01:39
16:37:48  pid=59219  runs=2  etime=01:47
16:37:56  pid=59219  runs=2  etime=01:55
```
pid 与 runs 全程不变 ⇒ 当前稳定，之前的变化是**全组轮番重启验证**造成的。

## 六、关于两份实现是否要合并

**当前不合并，但记录理由**：
- `ops-discipline.sh uptime`：给人**手动排查**用，带 pid/etime 明细，可单独调
- `health-audit.mjs` 的 `env.restart`：**体检报告**的一部分，跟随整体判定出报告
- 两者**数值与判定已验证一致**，且调用场景不同

**但这属于「已知的重复」，不是「设计上的分工」** —— 如果将来判据要改（比如窗口从 300s 改成 600s），
**必须两处同时改**。已在两份文件头部互注（`ops-8811`/`ops-monitor` 已有此先例）。
