# 房间级监控补盲 + 通用日志轮转（2026-11-22 17:02）

## 一、发现真盲区：`/api/status` 200 但房间 502

**现场复现（不是推演）：**
```
停掉 7788（magnet-search）
  curl :7788/            → code=000（0.2ms RST，进程已死）
  curl :8890/magnet/     → code=502
  curl :8890/api/status  → code=200   ←←← 盲区在这
```

**根因**：`/api/status` 只报告客厅进程自身状态，**不反映各房间反代上游的死活**。
今天 `/magnet/` 因 7788 死掉返回 502 时，`ops-monitor` 全程 `EXIT=0` —— **房间坏了监控不知道**。

**「客厅进程活着」≠「用户点得进去」，两者不能互相替代。**

## 二、修法：`ops-monitor.sh` 新增 `check_rooms`

```bash
for r in magnet book music vod download library notes calendar photos cast; do
  code=$(curl -s -o /dev/null -m 8 -w '%{http_code}' "http://$HOST:$PORT/$r/")
  [ "$code" != "200" ] && bad++ && detail="$detail $r=$code"
done
```
- 加入 `all` 与 `--json` 两个入口
- 新增子命令 `rooms` 单独查
- guard 调用 `ops-monitor.sh`，**自动继承**这条检查

## 四、通用日志轮转 `ops-rotate.sh`

原来的 `ops-rotate-8811.sh` 把目录与文件名写死（只管 lingting）。抽出通用版：

```bash
./scripts/ops-rotate.sh <日志目录> [--dry-run] [--keep N] [--prefixes a,b,c]
```
- 不给 `--prefixes` 就自动扫描目录下所有 `*.log`（排除已归档）
- **copytruncate，不 mv**（mv 走后进程仍写旧 inode，新文件永远空）
- 保留 14 天

### 修掉两个自己引入的缺陷

**缺陷1：`find -regex` 在 macOS 上失效**
```
-regex ".*/[^-]+-[0-9]\{8\}\.log"   → 命中 0 个
```
BSD find 的 `-regex` 是 emacs 方言，`[^-]+` 与 `\{8\}` 都不按预期工作。
**后果最危险**：过期归档永远不清理，看着"安全"，实际是判据失效。
改用 glob：`-name '*-[0-9][0-9][0-9][0-9][0-9][0-9][0-9][0-9].log'`（行为确定）。

**缺陷2：证据文件被当成活跃日志切分了**
```
切分前: err-20260101-historical.log
切分后: err-20260101-historical-20261122.log   ← 被改名了
```
**修法**：自动扫描时排除 `evidence-*` 与 `*-historical`，与 prune 的排除规则保持一致。
验证：切分后 `evidence-*` 与 `*-historical` 原样保留，只切了 actions/stdout。

### 三臂 + 关键臂
```
臂1 dry-run（客厅）        → EXIT=0  列出 3 个待切分文件
臂2 真实切分               → EXIT=0  归档 actions/guard/stdout
臂3 幂等（再跑）           → EXIT=0  "无需切分（当前日志为空）"
臂4 ★ 切分后仍能写         → pid 69757 未变、fd 仍指向原文件、
                            新写入 59B「spawn start.sh stop (pid 78180)」
                            ⇒ inode 保住，copytruncate 有效
```

## 五、又一条量具错误（今天第 N 次）

**现象**：全套联跑时 `ops-monitor` EXIT=2、`ops-8811` EXIT=2、`ops-discipline` EXIT=1。
**逐个单独跑：全部 EXIT=0。**

**根因**：我把多个脚本放在同一个 `for` 循环里密集连续调用，**它们互相竞争 8890**，
后跑的撞上前面请求造成的慢响应而超时。

**这不是脚本缺陷，也不是产品故障。** 与我此前那条「并发污染」是同一类。
**纪律**：性能/存活判据必须**独占窗口**跑，脚本之间至少间隔 1 秒。

## 七、`~` 未展开会静默失效

```bash
bash scripts/ops-rotate.sh ~/Library/Logs/wuwu-living --dry-run   # 在变量里时 ~ 不展开
```
`~` 只在命令行首由 shell 展开；放进变量/引号就变字面量，`[ -d ]` 失败但报错信息不指向真因。
**已加显式识别**：
```
判据故障: 路径里的 ~ 未展开（收到 [~/Library/Logs/wuwu-living]）
  改法：用绝对路径，如 scripts/ops-rotate.sh "$HOME/Library/Logs/wuwu-living"
```
exit=3（判据故障），不是静默报"无需切分"。
