# 端口纪律自检上线（2026-11-22 16:21）

## 背景：总管定的两条纪律，我把它做成可执行脚本

总管原话：
> 任何测试夹具不得使用 8811、8890、1122、7788、8317、12010 这些项目端口。
> 夹具一律从 19000–19999 取，且必须同时带 `WUWU_RUNTIME_DIR=/tmp/<唯一名>`。

**纪律写在群公告里没人执行 = 等于没有。** 所以做成 `scripts/ops-discipline.sh`：

```bash
bash scripts/ops-discipline.sh ports      # 项目端口是否被非预期进程占用
bash scripts/ops-discipline.sh fixtures   # 19000+ 夹具是否合规
bash scripts/ops-discipline.sh restart 8890 5   # 重启前记录预告
bash scripts/ops-discipline.sh            # 全量
```

退出码：`0=干净 1=告警 2=环境不洁（测量结论不可信）3=判据故障`

## 核心设计：端口「合法占用者」白名单

| 端口 | 期望进程 | 实际 |
|---|---|---|
| 8811 | `server.mjs` | ✅ |
| 8890 | `hub.mjs` | ✅ |
| 1122 | `reader` | 空闲 |
| 7788 | `mx.mjs` | ✅ |
| 8317 | `workbuddy`（二进制） | ✅ |
| 12010 | `grok-gateway.mjs` | ✅ |

**不是预期进程占用 → 判「环境不洁」，不给服务判级。** 这正是总管要的：今天所有人都在被自己污染的环境里互相否定。

## 修掉三个我自己引入的误报（这条最值得记）

### 误报1：`ps` 把中文路径转义 → 真服务被判「不洁」
```
8811 实际: /Users/wuwu/Doubao/.../聆听音乐网页版/server.mjs
ps 输出:   /Users/wuwu/Doubao/.../M-iM-!M-5M-gM^IM^H/server.mjs
→ grep "server.mjs" 匹配不上 → 8811 被判"不洁"
```
**修法**：不看整条 command，只看**尾部文件名**（ASCII 不受转义影响）。

### 误报2：只取 `$NF` → 文件名变成端口号
```
7788 命令行: mx.mjs serve 7788
$NF = "7788"    ← 取到端口号，不是文件名
```
**修法**：扫描所有参数，找第一个 `.mjs/.js/.py/.sh` 结尾的。

### 误报3（测量方法错，不是脚本错）：幂等比了时间戳
```
diff 两次输出 → 只差 "16:20:45" vs "16:20:46"
```
**幂等判据只能比判定内容，不能比时间戳/耗时。** 今天已经踩过第二次（上次是耗时 ms）。

## 与总管更正的关系（我接受的三处）

1. **`err.log` 不是 0 字节，是 1485 字节 / 5 条 `EADDRINUSE`** —— 我报 0 字节时它确实是空的（mtime 15:54 之前），后来被写入。**这正好说明 `/tmp` 日志会被清、也会被写，查根因必须看当时的快照，不能隔一小时再回头看。**
2. **`hub.mjs:1508` 的 5000ms 已不存在** —— `probe` 默认 800ms（`:246`），1508 现在是章节列表。**总管那条「8811 拖慢首页 1987ms」基于旧代码，应撤回。**
3. **9 次重启在 15:15–15:32，与全组起夹具的时间窗重合** —— 重启原因是端口冲突，不是修法让它停。

## 遗留
1. `restart` 子命令只**记录**预告，不会真的重启——故意的（重启要人决定）。但群公告那条「重启前先说一句」仍靠人执行，脚本只能留痕。
2. `fixtures` 检查靠命令行关键字（hang/fixture/fx/fake/probe-）识别夹具，**改个名就查不到**。更稳的做法是扫「监听 19000–19999 的进程」反查，但会把正常开发服务误伤，暂不做。
