## 任务二：存活判据（端口在听 ≠ 能用）

### 实验设计：造一个「accept 但不回包」的夹具
```js
net.createServer((s) => { s.on('error', () => {}); }).listen(8899)  // 收下连接，永不回包
```
四条判据同时问它：

| 判据 | 输出 | 判定 |
|---|---|---|
| A `lsof -iTCP:8899 -sTCP:LISTEN` | `node 16430 ... LISTEN` | **假绿** |
| C `ps -p 16430` | `16430 0.0`（进程在） | **假绿** |
| D 真实请求 `curl -m 2` | `code=000 t=2.005233 rc=28` | ✅ 判对 |

### 关键发现：`000` 必须再分两种
| 形态 | 耗时 | curl rc | 含义 | 用户感受 |
|---|---|---|---|---|
| **HUNG** | 2.005s（≈超时上限） | 28 | 端口在听、accept 后不回包 | 一直转圈 |
| **DEAD** | 0.000257s（毫秒级） | 7 | 内核 RST，根本没进程接 | 立刻打不开 |

**这两种修法完全不同，混成一个 `000` 会误导方向。** 这是本次最重要的产出。

### 交付：`scripts/ops-8811.sh`
退出码五值互斥：`0=ALIVE 1=DEGRADED 2=DEAD 3=HUNG 4=判据故障`

四条臂验证（退出码均不接管道取）：
```
臂1 挂起夹具 :8899   → EXIT=3  HUNG 3/3（端口在听、accept 后不回包）
臂2 无监听 :8898     → EXIT=2  DEAD 0/3（毫秒级 RST）
臂3 真 8811          → EXIT=0  ALIVE 5/5
臂4 坏 URL           → EXIT=4  判据故障
```

## 任务三：熔断是否真生效（决定性实验）

把**真 8811 停掉、换成挂起夹具**（复现总管描述的场景：端口在听、2s 超时），再打客厅 20 次：

```
8890 /api/status ×20：
0.901 0.809 0.009 0.009 0.008 0.009 0.008 0.014 0.008 0.006
0.007 0.008 0.006 0.007 0.007 0.006 0.007 0.006 0.007 0.007
→ 20/20 200，超 500ms 2/20，max 0.90s
```

**读法（这是熔断在工作的铁证）**：
- 前 **2 次**各约 **800ms** = `PROBE_BREAKER_FAILS = 2` × `probe` 超时 800ms
- 第 3 次起全部 **6–9ms** = 熔断打开，60s 内直接短路返回

对比总管测到的「挂起时首页 2422ms vs 正常 435ms（差 1987ms）」：
**现在挂起态下首页只付 2 次 × 800ms 的代价，之后完全不受影响。**
