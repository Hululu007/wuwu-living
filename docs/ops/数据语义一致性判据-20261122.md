# 新增判据：数据语义一致性（HTTP 200 ≠ 数据自洽）

## 一、盲区是什么

后端管家修完熔断后，生产态核实通过：三站 `fails=1 until=0 kind=timeout`（不再冻 10 分钟）、
错误文案不再带全角括号。**但我在同一份响应里读到一个自相矛盾的字段：**

```
非凡资源: ok=true  count=241  err="超时 2.5s 无响应"
```

`ok=true` 与 `error` 非空同时成立，且能稳定复现。

**根因**（`lib/vod_recs.mjs:399`）：
```js
ok,                     // = items.length > 0，有数据就算成功
error: fatal,           // = 首个失败原因，部分请求超时也会有值
```
两个变量语义独立、没有互斥，一起输出就矛盾。

## 二、★ 但我核过前端后，把它定成 WARN 而不是 FAIL

`public/assets/vod-recs.js:276-280`：
```js
var ok  = sources.filter(s => s.ok);
var bad = sources.filter(s => !s.ok);
foot.textContent = '来源 ' + ok.length + '/' + sources.length + ' 站在线'
  + (bad.length ? '：' + bad.map(s => s.name + '（' + s.error + '）').join('、') : '');
```

**`error` 只在 `!ok` 时被渲染。** 所以 `ok=true` 的 `error` **永远不会显示给用户**——
这是「数据脏」不是「用户可见缺陷」。判红会让 guard 因一个看不见的字段反复告警（告警疲劳）。

**反过来**：`ok=false` 且 `error` 为空，前端会渲染成 `电影天堂（）` 空括号——**用户可见**，必须 FAIL。

## 三、分级判据

| 形态 | 用户可见？ | 判据 |
|---|---|---|
| `ok=true` 且 `error` 非空 | ❌ 前端不渲染 | **WARN**（EXIT=1） |
| `ok=false` 且 `error` 为空 | ✅ 空括号 | **FAIL**（EXIT=2） |

### 三臂
| 臂 | 数据 | 结果 |
|---|---|---|
| 正向（当前生产） | `非凡资源 ok=true err="超时 2.5s 无响应"` | `WARN 脏字段（前端不渲染）` EXIT=1 |
| 负向（干净） | 2 活站 + 1 死站带文案 | `PASS 数据语义一致 3 个来源` EXIT=0 |
| 负向（空文案） | `死站C ok=false err=""` | `FAIL 失败但无文案` EXIT=2 |

## 四、落地

```

```
guard 调 `ops-monitor.sh`，自动继承——这个脏字段现在会被机器看见，不再靠人肉读 JSON。

## 五、这条判据的一般意义
`check_rooms` 只判 HTTP 200。今天证明了：**200 只能证明「服务在应答」，不能证明「应答说得通」。**
凡是「结构化响应里有多组互斥语义字段」（ok/error、status/message、success/reason），
都可能出现「两个字段各自为真、合起来矛盾」，而 HTTP 层永远看不出来。
