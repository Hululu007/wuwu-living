# 客厅日志从 /tmp 迁到持久目录（2026-11-22 16:46）

## 一、发现：6 处硬编码 `/tmp`，其中两处是崩溃兜底

排查 `/tmp` 大文件时发现客厅自己的关键日志全在 `/tmp`：

```
hub.mjs:63   uncaughtException      → /tmp/wuwu-book-search.log   ← 崩溃兜底
hub.mjs:66   unhandledRejection     → /tmp/wuwu-book-search.log   ← 崩溃兜底
hub.mjs:80   ACTION_LOG             → /tmp/wuwu-living-actions.log
lib/book_source_search.mjs:130      → /tmp/wuwu-book-search.log
lib/reader_api.mjs:67               → /tmp/wuwu-reader-api.log
lib/rooms.mjs:115                   → /tmp/wuwu-living-rooms.log
```

外加两个 plist 的 stdout/stderr：
```
com.wuwu.wuwu-living.plist       → /tmp/wuwu-living.log / .err.log
com.wuwu.wuwu-living-guard.plist → /tmp/wuwu-living-guard.log / .err.log
```

**实测体积**：`wuwu-book-search.log` 8.6MB、`reader-searchd.log` 11MB。

**为什么这是缺陷**（与 8811 当天同一个病）：
1. macOS 会清理 `/tmp` —— **崩溃证据可能在被查到之前就消失**
2. 8811 那 5 条 `EADDRINUSE` 就是靠 `/tmp` 残留才查出来；文件空的话根因至今不明
3. `/tmp` 全局共享，任何进程（含测试夹具）都能写同名文件
4. 无轮转，实测已 8.6MB

## 二、为什么不用 runtime/

`runtime/` 是**数据目录**（json、书源、实例锁），已 gitignore。把日志放进去有两个坏处：
- 实验实例用 `WUWU_RUNTIME_DIR` 换走整个 runtime ⇒ **日志跟着分叉**，查崩溃时不知看哪个
- 数据备份/迁移会连日志一起搬，日志本不该被备份

⇒ 独立到 `~/Library/Logs/wuwu-living/`，与 8811 的 `lingting/` 同构。

## 三、交付：`lib/log_dir.mjs`

```js
export const LOG_DIR      // ~/Library/Logs/wuwu-living
export function logPath(name)
export function appendLog(name, line)   // 任何异常都吞掉
```

**`WUWU_LOG_DIR` 可覆盖** —— 测试夹具用它，避免污染真实日志目录。

**`appendLog` 必须吞异常**：它被崩溃兜底路径调用，日志写失败绝不能再抛。
