## 二、`logs` 子命令我独立跑了正负两臂

```
臂1 正向（/tmp 已清）    → EXIT=0
    "OK 持久目录: /Users/wuwu/Library/Logs/lingting"
    "PASS /tmp 无 lting 日志残留"

臂2 负向（造 /tmp/lting.log 13 字节）→ EXIT=1
    "警告 /tmp 残留死文件: /tmp/lting.log（13 字节，mtime 11-22 16:28）"
    "← 服务已不再写它；留着会让「日志没在写」看起来像真的"
    "提示 1 份 /tmp 残留，确认内容已归档后应删除"
```
负向臂精确报出**字节数 + mtime**，不是笼统说「有残留」。

## 三、我自己的脚本：职责重复，退役

| 项 | 我的 `ops-cleanup-tmp-logs.sh` | 总管的 `ops-discipline.sh logs` |
|---|---|---|
| 职责 | **删除** /tmp 残留 | **检测** /tmp 残留 |
| 定时 | `com.wuwu.lingting.tmpclean` 每天 05:10 | 随 `all` 跑 |
| 现状 | /tmp 已空 ⇒ 无事可做，每天空跑 | 持续有效 |

**判断**：`/tmp` 两份已被清（`cmp` 逐字一致 + fd 不再指向），
我的脚本唯一职责「删残留」已无事可做；而「以后不许再出现两份真相」这个检测职责已由 `logs` 承担。
**留着 = 第二份实现 = 又一次「两份真相」。**

### 退役动作（都可回滚）
```
1. launchctl bootout com.wuwu.lingting.tmpclean
   验证：launchctl print ... → EXIT=113（已卸载），不是 0
   ★ 注意：`bootout` 自己的返回码不可信，必须用 `print` 的退出码复核
```

## 教训（今天第五次同类）

**同一件事做两遍 = 两份真相。**
今天出现过三次同型问题：
1. 8811 日志在 `/tmp` 和 `~/Library/Logs` 各一份 → 结论取决于你 `ls` 哪个目录
2. `ops-8811.sh` 的 IMPOSTOR 有两份实现（我和总管各写一份）→ 不知哪份生效
3. `ops-cleanup-tmp-logs.sh` 与 `ops-discipline.sh logs` 职责重叠 → 就是本条

**共同点：两个东西都对，但「谁生效」不确定。** 这比"有一个是错的"更难查，
因为两个单独跑都能过。**收敛方式：保留一个，另一个归档并写明为什么。**
