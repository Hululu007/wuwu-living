# 重启窗口裁决 + 漂移检测（2026-11-22 15:57）

## 结论：**这次不需要重启**

总管要求的重启窗口，我查完后判定**不执行**，理由是可实测的：

```
进程 pid=3591      启动 2026-11-22 15:42:46
hub.mjs mtime              2026-11-22 15:39:51   ← 早于启动 ✅
lib/rooms.mjs              2026-11-22 15:22:53   ← 早于启动 ✅
lib/photos.mjs             2026-11-22 15:22:53   ← 早于启动 ✅
lib/legacy_shell.mjs       2026-11-22 15:22:08   ← 早于启动 ✅
```

**后端代码全部早于进程启动 ⇒ 运行的就是最新代码。**

旁证：总管说之前 `/api/book/groups` 返回 404，现在实测：
```
curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:8890/api/book/groups
→ 200
```

## 关键区分：为什么静态资源晚于进程不算漂移

有 13 个 `public/**` 文件的 mtime 晚于进程启动（15:45–15:47）。我实测了它们是否需要重启：

```bash
# 往 room.css 末尾追加一行
echo "/* drift-probe-$(date +%s) */" >> public/assets/room.css
sleep 0.5
curl -s http://127.0.0.1:8890/assets/room.css | tail -c 60
→ /* drift-probe-1795334125 */          ← 立即读到
```

**静态资源每次请求读盘，改完立即生效，不需要重启。**
所以「mtime 晚于进程启动」不能一律报漂移——否则 13 个静态文件会产生假警报，把真正需要重启的后端漂移淹没掉。

## 交付：`scripts/ops-drift.sh`

判据分两类（这是脚本的核心）：
| 类别 | 文件 | 判定 |
|---|---|---|
| 后端代码 | `hub.mjs` `lib/*.mjs` `package.json` | mtime > 进程启动 ⇒ **FAIL 需重启** |
| 静态资源 | `public/*.html` `public/assets/*` | 只统计数量，不报警（每请求读盘） |

### 四臂验证（退出码均不接管道取）
```
臂1 正向（当前真实状态）      → EXIT=0  PASS 无后端漂移（静态资源 13 个较新，无需重启）
臂2 负向（touch lib/rooms.mjs）→ EXIT=1  FAIL 精确点名 lib/rooms.mjs 11-22 15:55:48
臂3 区分力（只 touch room.css）→ EXIT=0  PASS 静态较新不报错 ← 证明假警报被正确抑制
臂4 幂等（连跑两次）          → EXIT=0/0 输出逐字一致
```

臂3 是最重要的一条：**只有证明「静态资源较新不会误报」，臂2 的 FAIL 才有意义。**

## 一个副作用要记
我用 `cp` 还原 `room.css` 时把它的 mtime 改成了 15:55:26（原为 15:45:58）。
**内容经 `cmp` 校验一致**，只是时间戳变了。这会影响后续按 mtime 排序的判断，故记录在此。
正确还原姿势应是 `cp -p`（保留 mtime），我第一处用了 `cp`、后两处改用了 `cp -p`。
