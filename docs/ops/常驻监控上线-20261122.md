| 要求 | 实现 | 状态 |
|---|---|---|
| ① 入口存活：`curl 8890/api/status` 必须 200，连续 3 次失败告警 | `ops-monitor.sh` check_entry（3 次真实请求） | ✅ |

| ③ 实验实例隔离：`PORT=889x` 必须带 `WUWU_RUNTIME_DIR` | `ops-monitor.sh` check_isolation | ✅ |

**但脚本能手动跑 ≠ 常驻。** 之前一直缺这一环，本轮补上：
`com.wuwu.wuwu-living-guard.plist`，`StartInterval = 300`（每 5 分钟）。

```
launchctl print gui/501/com.wuwu.wuwu-living-guard
→ state = not running      ← StartInterval 型任务的正常态（跑完就退）
→ runs = 1                 ← 已执行过
→ last exit code = 0
→ run interval = 300 seconds
```

★ `state = not running` 对 `StartInterval` 型任务是**正常**的，不是故障。
判它有没有在工作，看 `runs` 涨不涨 + 状态文件有没有被写。

## 告警去重（不做这个会刷屏）

`ops-guard.sh` 的策略：
- **第 1 次失败立刻告警**（入口挂了要马上知道，不等第 3 次）
- 之后每 3 次再提醒（`cnt % 3 == 0`）
- 恢复时推一条 `RECOVERED`（否则用户永远不知道好了没）

实测 7 次连续故障：
```
第 1 次 → state=bad cnt=1
第 2 次 → state=bad cnt=2
第 3 次 → state=bad cnt=3
... 第 7 次
告警条数 = 3（cnt 1 / 3 / 6）      ← 不是 7 条
```

## 五臂验收（退出码均不接管道取）

```
臂1 正常服务            → EXIT=0  日志 0 行（不推假告警）
臂2 首次运行即故障      → EXIT=2  ALERT=1
臂3 连续故障 6 次       → ALERT=3（cnt 1/3/6，去重生效）
臂4 故障→恢复           → RECOVERED=1
臂5 恢复后再跑 2 次     → RECOVERED 仍为 1（幂等）
```

## 修掉两个我自己引入的缺陷

### 缺陷1：首次运行推假 RECOVERED
状态文件不存在时 `prev=unknown`，服务本来正常却被判成「恢复」，推了一条假告警。
**修法**：只有 `prev = bad` 才推恢复通知。备份 `ops-guard.sh.bak-20261122-1604-firstrun`。

### 缺陷2：`(never exited)` 被当成异常退出码
`launchctl` 在「从未退出过」时输出的是文本 **`(never exited)`**，不是数字。
我原来的 `tr -d ' '` 把它压成 `(neverexited)`，再和 `0`/`143` 比较 → 判成异常 → **健康服务被误报 WARN**。
实测现场：刚 bootstrap 的 pid=21920 被报 `lastExit=(neverexited) ← launchd 报 running 但上代异常退出`。

**修法**（`ops-monitor.sh`，备份 `.bak-20261122-1606-neverexit`）：
```bash
case "${lexit:-}" in ''|*[!0-9]*) lexit=0 ;; esac   # 非纯数字一律视为 0
```

回归六种输入：
```
(neverexited)  → PASS      ← 修复前这里报 WARN
(never exited) → PASS
空             → PASS
0              → PASS
143            → PASS
1              → WARN      ← 真实异常码仍能抓到，没被修坏
```
