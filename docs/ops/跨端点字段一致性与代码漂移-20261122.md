## 二、★ 后端管家说的「/api/status 没同步」是真的，而且会造出第三种假空

**实测字段对照：**
```
/api/book/info      → stale=false untrusted=false dbOk=true      （18 键）
/api/status 的 book → stale=false untrusted=undefined dbOk=undefined
```

**源码定位**（`hub.mjs` appStatus 的 book 返回块）：
```js
pending: !!b.pending,
stale:   !!b.stale,
ageMs:   b.ageMs == null ? null : b.ageMs,
// untrusted 与 dbOk 没有透出
```

**为什么这会造成假空**（前端 `五五客厅.html:902` 消费的是 status 那一份）：
```js
var pending = ab.pending === true;
var stale   = ab.stale === true;
var blank   = pending ? '获取中…' : (stale ? '刷新中…' : null);
var sourcesText = (typeof sb.sources === 'number' && isFinite(sb.sources))
  ? sb.sources.toLocaleString('en-US') : (blank || '0');   ← 落到 '0'
```
一旦 `dbOk=false` 但 TTL 未过期：info 侧 `untrusted=true / stale=false / sources=null`，
status 侧 `untrusted` 丢失、`stale=false` ⇒ `blank=null` ⇒ 首页显示 **「0 条书源」**。

**这是「把没取到伪装成 0」的第三种假空**，与 `sources`、`groupTotal` 那两条同源。

## 三、新判据：跨端点字段一致性

`check_xendpoint`：只查**字段存在性**，不比较值（两边取值时机不同，值可以不一样）。
```
info 有的语义字段（stale/untrusted/dbOk/pending），status 的 book 项是否也透出
```

### 三臂
| 臂 | 条件 | 结果 |
|---|---|---|
| 正向（当前生产） | status 缺 untrusted/dbOk | `WARN 跨端点字段不一致 缺: untrusted,dbOk` EXIT=1 |
| 负向（同一靶子，字段齐全） | 全透出 | `PASS 跨端点字段一致` EXIT=0 |
| 正向对照（同一靶子，删字段） | 缺 untrusted/dbOk | `WARN` EXIT=1 |

★ 臂2 与臂3 用的是**同一个靶子进程**，只切换返回体——排除了「靶子不同」这个混淆变量。

**定级为 WARN 不判 FAIL 的理由**：当前 `dbOk=true`，首页显示正常；缺字段是**潜在**假空，
不是已发生的用户可见故障。判红会让 guard 因一个尚未发作的缺口反复告警。
