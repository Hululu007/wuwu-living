# 夹具判据：区分「遗弃」与「活跃」+ 竞态幽灵（2026-11-22 17:58–18:05）

## 一、修掉的假红：有人跑测试 = 环境脏

原判据：「19000-19999 有监听且无 `WUWU_RUNTIME_DIR`」一律 FAIL。

实测 3 个 `node srv.mjs` 同批（17:15 起，cwd `/private/tmp/btest`）：

| pid | 端口 | PPID | 真实状态 |
|---|---|---|---|
| 37456 | 19055 | 37454（bash 仍在） | **活跃**，别人的测试在跑 |
| 38024 | 19059 | **1** | **遗弃**，父 shell 已死 |
| 38153 | 19058 | **1** | **遗弃** |

后果：别人一跑测试，整轮 `ops-discipline` 就退 2。等于「有人在干活」被判成「环境脏」，
会逼所有人不敢跑测试——这比漏报更伤协作。

**修法**：按 PPID 分两类
```
PPID=1        → 遗弃（没人会回收）→ 计入 FAIL，红
PPID 存活     → 活跃（有主）      → 只提示，不判红
```

## 二、修掉的第二个缺陷：竞态幽灵

lsof 列出 pid 后、读 `ps` 之前进程可能已退出，此时 `ppid_now` 与 `ports` 都为空，
被判成「PPID=1 遗弃夹具」。实测连跑三次遗弃数 **2 / 2 / 3**，第三次多出
`pid=24674 端口=无 命令=空` 的幽灵。

**修法**：`ppid_now` 为空 ⇒ 打印「已退 pid=N 扫描时已退出（竞态），不计入」并 `continue`。

## 三、三臂验证

| 臂 | 条件 | 结果 |
|---|---|---|
| 负向（抓取力） | 造 PPID=1 夹具占 19079 | `遗弃 pid=31899 端口=19079` 精确命中，FAIL 3 |
| 负向（幂等前置） | 清理后复查 | 遗弃数 3 → 2 |
| 正向 | 活跃夹具 37456（PPID 37454） | `活跃 ... 有主，不判红`，不计 FAIL |
| 幂等 | 连跑 5 次 | 遗弃=2 幽灵=0 FAIL=2，**五次恒定** |
