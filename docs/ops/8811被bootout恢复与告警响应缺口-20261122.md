# 8811 被 bootout 后恢复 + 一个必须认的响应缺口（2026-11-22 21:10–21:15）

## 一、先纠正一条错误因果链

后端管家报告「连续 EADDRINUSE → launchd 放弃 → 卸载托管项」。**这条不成立。**

**证据一：err.log 是 4 小时前的旧记录**
```
err.log  mtime = 2026-11-22 17:00:53   只有 2 行 EADDRINUSE
out.log  mtime = 2026-11-22 17:01:03   最后三行都是正常启动
```
8811 在 17:01 之后一直活着（pid 96270），**17:00 的 EADDRINUSE 与 21:02 的停止无关**。

**证据二：launchd 自己说了是「移除服务」，不是「反复失败后放弃」**
```
log show --predicate 'process=="launchd" AND eventMessage CONTAINS "lingting"' --last 30m
2026-11-22 21:02:37  launchd: service inactive: com.wuwu.lingting.web
2026-11-22 21:02:37  launchd: removing service: com.wuwu.lingting.web
```
**`KeepAlive=1` 自己永远不会 `removing service`** —— 那是 `launchctl bootout`（或 `unload`）的产物。
`launchctl print-disabled` 也无 lingting 条目，说明不是 `disable -w`，是一次普通 bootout。

**准确表述**：8811 在 **21:02:37 被人 bootout 卸载**，与 EADDRINUSE 无关。
`restarts.log` 里 `21:02:51 DOWN(auto) 8811(96270→none)` 是 guard 事后记账，不是原因。

## 四、guard 的 `last exit code = 2` 不是故障
```
state = not running    runs = 50    last exit code = 2    run interval = 300
```
`StartInterval=300` 型任务空闲时 `not running` 是正常态；**退出码不参与调度**（与 KeepAlive 型不同）。
心跳 `21:02:51` / `21:08:01` 两次都在，证明它每轮都在跑。
