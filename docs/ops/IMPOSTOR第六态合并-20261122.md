# IMPOSTOR 第六态：合并重复实现 + 六臂验收（2026-11-22 16:27）

## 发现：磁盘上有两份 IMPOSTOR

总管说「我已替你实现」，我核对时发现**磁盘上确实有两份**：

```
:106-111   我那份，带 `if [ "$ok" -gt 0 ]` 守卫
:125-130   总管那份，放在 `elif [ "$ok" -eq "$N" ]` 分支里
```

功能重叠、注释重复（`5=IMPOSTOR` 出现三次）。**两份都留着会让人不知道哪份生效。**

## 合并时保留的关键判据：`ok > 0` 前提

这不是可有可无的守卫，是**实测踩出来的**：

```
无条件核对身份 → 挂起夹具（accept 但不回包）也满足 pid≠托管pid
                → HUNG 被误报成 IMPOSTOR
                → 把「服务卡住」说成「有人冒充」，方向完全错
```

实测证据（我这一轮真的踩到了）：
```
URL=:19997（挂起夹具）  → 修复前报 IMPOSTOR exit=5（错）
                        → 修复后报 HUNG    exit=3（对）
```

**IMPOSTOR 的严格定义**：端口**正常回答 200**，但回答者不是 launchd 托管的那个 pid。
所以前提必须是 `ok > 0`——没有 200 就谈不上「冒充」。

## 顺带堵掉一个潜在假绿

原 `elif [ "$ok" -eq "$N" ]` 在 `-n 0` 时会变成 `0 == 0` 成立 → 报 ALIVE。
加了 `[ "$N" -ge 1 ]` 前置条件。

## 六臂验收（退出码均不接管道取）

```
臂1 IMPOSTOR(19999 假服务返 200) → EXIT=5  期望 5  ✅
    "端口 19999 被非托管进程占用（监听 pid=32201，launchd 报 pid=23493）"
臂2 HUNG(19997 accept 不回包)    → EXIT=3  期望 3  ✅
臂3 DEAD(19998 无监听)           → EXIT=2  期望 2  ✅
臂4 ALIVE(真 8811)               → EXIT=0  期望 0  ✅
臂5 ALIVE(8890 客厅)             → EXIT=0  期望 0  ✅
臂6 判据故障(坏 URL)             → EXIT=4  期望 4  ✅
```

**臂2 是这次合并最重要的验证**：如果 `ok>0` 守卫被删掉，臂2 会变 exit=5，
看起来「也报错了」，但报错了**原因**——把 HUNG 当 IMPOSTOR 会让人去查「谁占了我的端口」，
而真正的问题是「服务卡住了」。
