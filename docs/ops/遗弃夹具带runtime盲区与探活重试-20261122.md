# 遗弃夹具盲区（带 runtime 被判 OK）+ 上游探活重试（2026-11-22 18:20–18:30）

## 一、★ 上一轮我自己留下的盲区：带 runtime 的遗弃夹具被判 OK

上一轮我把「PPID=1 ⇒ 遗弃」的判定**嵌在「无 runtime」分支里**，于是：

```
pid=10356  ./hub-fixture-t6.mjs  PPID=1  存活 29 分钟  CPU 13.28s（早跑完）
           runtime=/tmp/ww-t6    判据输出：OK    ← 错
```

**runtime 目录只说明「它声明了隔离」，不说明「还有人会来收它」。**
带 runtime 的遗弃夹具同样占端口、同样污染 19000 段。

**修法**：把 PPID=1 判定提到 runtime 检查**之前**，与 runtime 无关。

| 修前 | 修后 |
|---|---|
| `OK  pid=10356 端口=19049 runtime=/tmp/ww-t6` | `遗弃 pid=10356 端口=19049 PPID=1（父进程已死）runtime=/tmp/ww-t6` |

### 三臂
| 臂 | 条件 | 结果 |
|---|---|---|
| 负向 | 带 runtime 且 PPID=1（10356） | 判「遗弃」计入 FAIL |
| 正向 | 带 runtime 且 PPID 存活（造 19093） | 判 `OK`，不判红 |
| 幂等 | 连跑 5 次 | 遗弃数恒定 **1**（修复前该场景是 0，因为被判 OK） |

清理：10356 已 `kill`，`out.log` 250B 留证（`bind ok in 414ms → :19049`），19049 释放。

## 二、上游探活加重试（我与后端管家各自提过同一条）

原实现每上游**只 curl 一次**，瞬时抖动（GC / 连接排队 / 恰好在重启）会把 PASS 直接变 WARN。

**改法**：首次失败后间隔 1s 重试，最多 3 次，任一次 200 即通过。
**只影响「当下」这个数字，不影响「托管项是否存在」**——托管丢失是 `launchctl print` 查不到，与请求成败无关。

### 三臂
| 臂 | 条件 | 结果 |
|---|---|---|
| 正向 | 三上游正常 | 三条全 PASS |
| 负向（关键） | 真 `bootout` magnet | 仍报 `WARN magnet :7788 托管项丢失 当下=000`，耗时 **2.175s**（证明重试真跑了，没吞故障） |
| 抖动吸收 | 造「首次掐断、后续通」的端口 19094 | 单次直打 `000` → 带重试 `attempt1 → 200`，判 PASS |

恢复 magnet 后：`7788 → 200`、`/magnet/ → 200`、三上游全 PASS。
