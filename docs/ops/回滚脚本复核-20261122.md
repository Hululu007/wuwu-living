## 一、总管两处修复：diff 逐行核对，**都对**

```diff
- read -r code ctype size <<EOF
- $(curl ... -w '%{http_code} %{content_type} %{size_download}' ... || echo "000 - 0")
+ got=$(curl ... -w '%{http_code}|%{content_type}|%{size_download}' ... || echo "000|-|0")
+ IFS='|' read -r code ctype size <<EOF
```

| 修复 | 机制 | 我的复核 |
|---|---|---|
| ① 分隔符改 `\|` | `%{content_type}` 含空格（`text/html; charset=utf-8`），`read` 按空格切会把 size 取成 `charset=utf-8 29583` | ✅ 对，且我原来那版就是这么错的 |
| ② `000` 重试 3 次 | `/music/` 冷路径 1.28s 偶发超时，单次判死会误报 | ✅ 对，但**引入了一个新缺陷**（见下） |

## 二、我复核时发现并修掉的新缺陷

**现象**：死端口下 `size` 被解析成 `0000|-|0` 这种非数字乱值，打印成 `0000|-|0B`。

**根因**：`curl` 连接失败时**仍会输出 `-w` 内容**（`http_code=000`）**并返回非零**；
`|| echo "000|-|0"` 于是又追加一行 ⇒ `got` 变成两行 ⇒ `read` 只读第一行、剩余塞进 `size`。

**修法**（`scripts/ops-rollback.sh`，备份 `.bak-20261122-1555-fix-gotparse`）：
```bash
got=$(curl ... || true)                       # 去掉 || echo，改为 true
got=$(printf '%s\n' "$got" | head -1)         # 只取第一行
case "$got" in [0-9][0-9][0-9]\|*\|[0-9]*) : ;; *) got="000|-|0" ;; esac   # 校验形状
case "${size:-}" in ''|*[!0-9]*) size=0 ;; esac                            # 非数字归零
```

## 四、我自己犯的测量错（值得记）

第一次跑负向臂时我写的是：
```bash
PORT=9 bash scripts/ops-rollback.sh verify 2>&1 | tail -18; echo "EXIT=$?"
```
拿到 `EXIT=0`，差点报成「12 项 FAIL 但退出码是 0」的严重缺陷。
**实际 `EXIT=1`** —— 那个 0 是 `tail` 的退出码。

正确写法：
```bash
PORT=9 bash scripts/ops-rollback.sh verify > /tmp/v9.txt 2>&1; echo $?   # → 1
```
这条总管已经强调过，我还是踩了。**凡是汇报里出现 exit=N，N 必须在不接管道的命令上取。**
