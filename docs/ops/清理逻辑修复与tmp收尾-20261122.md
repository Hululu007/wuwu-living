# 日志清理逻辑修复验证 + /tmp 双份真相收尾（2026-11-22 16:32）

## 一、总管指出的缺陷：我的清理 glob 会删掉唯一证据

**我原脚本的清理逻辑**：
```bash
find "$LOG_DIR" -name 'out-2*.log' -mtime +14 -delete
find "$LOG_DIR" -name 'err-2*.log' -mtime +14 -delete
```

**缺陷**：`err-2*.log` 会匹配 `err-20261122-historical.log`——
那是 16:20 抢救出来的、**今天唯一能解释 8811 反复重启的 5 条 `EADDRINUSE` 证据**。
14 天后静默删除。**「日志轮转把唯一证据删了」比「日志不轮转」危险得多。**

## 二、我的独立验证（不采信结论，自己造对照）

### 正反对照（同一套测试文件，两种 glob）
```
测试集（前三个 mtime 已改老到 2026-01）：
  out-20260101.log                          ← 切分产物，应删
  err-20260102.log                          ← 切分产物，应删
  err-20260101-historical.log               ← 证据，应留
  evidence-20260101.log                     ← 证据，应留
  out-20261122.log                          ← 今天，应留

旧 glob（-name 'err-2*.log'）：
  会删: err-20260102.log
  会删: err-20260101-historical.log    ← ❌ 证据被删，缺陷复现
  剩余: evidence-20260101.log

新逻辑（-regex '.*/err-[0-9]{8}\.log' ! -name 'evidence-*'）：
  清理 out: 1 个   清理 err: 1 个
  剩余: evidence-20261122-err-EADDRINUSE.log
        evidence-20261122-out-banner.log
        out-20261122.log              ← ✅ 证据与今日日志全留
```

**正反对照才是证据**：只跑新逻辑"看起来没删证据"不够，
必须证明**旧逻辑确实会删**，才知道修的不是一个假想问题。

## 三、/tmp 双份真相收尾（总管提的「下一轮做成带时间条件」）

现在 `/tmp/lting.log`(225B) 和 `/tmp/lting.err.log`(1485B) 还在，
与 `~/Library/Logs/lingting/evidence-*` 内容**逐字一致**（`cmp` 验证过）——
留着会造成「两份真相」，以后查问题时可能看到过时的那份。

但不能立刻删。交付 `scripts/ops-cleanup-tmp-logs.sh`，**四条判据全满足才删**：

| 判据 | 为什么必须有 |
|---|---|
| ① 进程 fd 真的指向新路径（`lsof`，不是看 plist） | 配置改了 ≠ 生效了 |
| ② `/tmp` 两份 mtime 不再增长 | 证明进程确实不再写它们 |
| ③ 已过 ≥24h（`STABLE_HOURS`） | 新路径要稳定运行过一段时间 |
| ④ 持久版 `evidence-*` 与 `/tmp` 原件 `cmp` 逐字一致 | 内容没被完整保存就不能删原件 |

### 三臂验证
```
臂1 正常跑                → EXIT=1
    PASS ① fd 指向新路径 (pid=40314)
    PASS ④ /tmp/lting.log 内容已被 evidence 完整保存
    等待 ③ 仅 0h < 24h，暂不删        ← 时间门生效
    "本次不删除任何文件（判据未全满足）"

臂2 负向：篡改 /tmp 内容  → EXIT=1
    "拒绝删除: /tmp/lting.log 与 evidence-... 内容不一致，先人工确认"

臂3 负向：8811 无监听     → EXIT=1
    "跳过: 8811 无监听进程，无法证明新路径在生效"
```

**臂2/臂3 是防「盲删」的**：内容没保存全、或无法证明新路径生效时，一律不删。
